# 地图站功能与配置说明

> 适用文件：`index.html`、`scripts/build.py`
> 最后更新：2026-11-11

本文说明地图站（`map.2rtk.com`）的底图策略、密钥配置、中英双语、SEO 与导航结构，以及常见改动方式。

---

## 一、关于「Cesium 自带的免费图源」

### 结论：能用，但不能只靠它

CesiumJS 内置的无需密钥图源只有一个：

```js
new Cesium.OpenStreetMapImageryProvider({ url: 'https://tile.openstreetmap.org/' })
```

官方 Viewer 文档的示例也正是这个。但实测结果（2026-11，中国大陆网络）：

| 图源 | 结果 | 说明 |
|------|------|------|
| `tile.openstreetmap.org` | **连接超时** | 国内基本不可达 |
| `services.arcgisonline.com`（Esri Imagery） | 超时 | 该子域不可达 |
| `server.arcgisonline.com`（Esri） | **200 / 1.9s** | 可用 |
| `basemaps.cartocdn.com`（CARTO，无子域） | **200 / 0.8s** | 可用 |
| `a.basemaps.cartocdn.com`（带子域） | 超时 | 该子域不可达 |
| 天地图（无合法 Key） | 418 | 可达但被 TEAP 拦截，需合法 Key |
| 高德 / 腾讯 | 200 | **禁用**，见下节 |

所以最终方案不是「用某一个免费源」，而是**准备多个源，启动时自动挑一个能用的**。

### ⚠️ 为什么绝不能用高德 / 腾讯地图

高德、腾讯、百度等国内图源使用 **GCJ-02（火星坐标）**。RTK 基准站是厘米级定位，把这些站点的 WGS84 坐标叠加到 GCJ-02 底图上，会出现 **数百米偏移**，直接让「基准站覆盖范围」这个功能失效。

可用且坐标兼容的是：

- **Esri World Imagery** — WGS84 / Web Mercator，全球
- **CARTO** — 基于 OpenStreetMap，WGS84 / Web Mercator，全球
- **天地图** — CGCS2000，与 WGS84 差异在厘米级，中国区最优

## 二、多图源自动降级机制

### 探测顺序（`BASEMAPS` 数组，按优先级）

| # | id | 名称 | 需要凭证 | 坐标基准 |
|---|----|------|---------|---------|
| 1 | `ion` | Cesium Ion（Bing 影像） | `CESIUM_ION_TOKEN` | WGS84 |
| 2 | `esri-imagery` | 卫星影像 | 无 | WGS84 |
| 3 | `carto-voyager` | 街道地图 | 无 | WGS84 |
| 4 | `tianditu` | 天地图影像 | `TIANDITU_TOKEN` | CGCS2000 |
| 5 | `osm` | OpenStreetMap | 无 | WGS84 |
| — | `carto-dark` | 深色地图 | 无 | 仅手动可选 |

### 工作流程

```
页面加载
  └─ 立即创建 Viewer（baseLayer: false）→ 站点与卫星先渲染，不阻塞
       └─ 按顺序探测图源
            ├─ 无凭证的源跳过（标记「需配置」）
            ├─ 加载一张 z=2 的瓦片，5 秒超时
            ├─ 成功 → 挂载为底图，停止探测
            └─ 失败 → 换下一个
                 └─ 全部失败 → 不显示底图，站点坐标仍然准确
```

探测用的是 `new Image()` 加载真实瓦片，不是 ping 域名——这样能识别「域名通但瓦片 403 / 需要 Key」的情况。

用户也可以点底部「底图」按钮手动切换，面板里会显示每个源的状态：**可用 / 不可达 / 需配置 / 未探测**。

### 为什么要串行而不是并行

并行探测会产生 5~6 个无用请求，且在弱网下互相抢占带宽。串行只在第一个源失败时才发下一个请求，用户几乎无感知（Esri 通常 1~2 秒返回）。

## 三、天地图 Key 怎么配（重点）

### 当前状态：代码里是空字符串

```js
var TIANDITU_KEY = typeof RUNTIME_CONFIG.tiandituToken === 'string'
  ? RUNTIME_CONFIG.tiandituToken.trim() : '';
```

项目里**没有任何硬编码的天地图 Key**，也**不包含任何小程序相关的 Key**（已全仓库检索确认）。`config.js` 里对应字段是空值：

```js
window.__2RTK_CONFIG = {"cesiumIonToken":"","tiandituToken":"","siteOrigin":"...","homeOrigin":"..."};
```

### 申请时必须选「浏览器端」

这是最容易踩的坑。天地图控制台创建应用时，「应用类型」有三个选项：

| 应用类型 | 能否用于本页面 | 说明 |
|---------|--------------|------|
| **浏览器端** | ✅ 可以 | 唯一可用于网页前端 |
| 服务端 | ❌ 不行 | 会返回 403，只在后端 Python/Node 里能用 |
| 小程序端 | ❌ 不行 | 只对微信小程序域名白名单生效 |

**请单独申请一个「浏览器端」Key**，不要复用小程序那个——小程序 Key 有独立的白名单和配额，混用会导致小程序侧调用失败。

申请地址：<https://console.tianditu.gov.cn/api/key>（个人开发者免费，日配额足够本场景）

### 配置方式

Cloudflare Pages 环境变量里加：

```
TIANDITU_TOKEN = 你的浏览器端Key
```

构建时会写入 `dist/config.js`，不会进入 Git 仓库。

### 不配天地图会怎样

完全不影响使用。页面会自动用 Esri 或 CARTO，只是在中国大陆访问速度可能不如天地图。天地图的定位是**备选加速源**，不是必需项。

## 四、中英双语

### 切换方式

- 顶部右上角按钮：中文界面显示 `EN`，英文界面显示 `中文`
- URL 参数：`?lang=zh` / `?lang=en`（优先级最高，方便搜索引擎区分版本）
- `localStorage` 记住上次选择
- 首次访问按 `navigator.language` 自动判断（`zh*` → 中文，其余 → 英文）

### 翻译范围

| 区域 | 是否翻译 |
|------|---------|
| 顶部导航 | ✅ |
| 底部控制按钮（暂停旋转 / 卫星标签 / 站点标签 / 覆盖范围 / 底图） | ✅ |
| 数据更新时间信息栏 | ✅ |
| 站点 / 卫星信息框字段名 | ✅ |
| 底部关键词条 | ✅ |
| **左侧数据源按钮（2RTK / CRTK / RTK2 / IGS Network / World）** | ❌ 保持原样 |

左侧数据源按钮按需求**固定不翻译**——这些是 Caster 的专有名称，翻译反而会造成混淆。

### 新增文案

在 `index.html` 的 `I18N.zh` 和 `I18N.en` 两个对象里同时加键，然后调用 `t('key')` 即可。只加一边会导致另一边回退到英文。

## 五、SEO 实现

### 已做的项

| 项 | 位置 | 说明 |
|----|------|------|
| `<title>` | head | 「全球免费 RTK 基准站地图 \| 2RTK NTRIP Caster 基站可视化」，含核心关键词 |
| `meta description` | head | 覆盖 RTK 基准站、NTRIP Caster、GNSS、免费测试等语义 |
| `meta keywords` | head | 现代搜索引擎权重低，但对部分中文引擎仍有参考价值 |
| `canonical` | head | `https://map.2rtk.com/` |
| `hreflang` | head | `zh-CN` / `en` / `x-default`，用 `?lang=` 区分，符合规范 |
| Open Graph | head | 微信、Facebook、Twitter 分享卡片 |
| JSON-LD | head | `Organization` + `WebSite` + `WebApplication`（含 `offers: 0 元`） |
| `<h1>` | body | `sr-only` 隐藏，视觉不影响地图，但给爬虫明确主题 |
| `<noscript>` | body | 完整的中文介绍段落，JS 不被执行时也有内容 |
| 底部关键词条 | body | 默认可见的一行文字，爬虫可读 |
| 顶部导航 | body | 真实 `<a href>` 链接，不是 JS 跳转 |
| `robots.txt` | 构建生成 | `Allow: /` + sitemap 地址 |
| `sitemap.xml` | 构建生成 | 含 `lastmod`，构建时自动更新 |

### 需要注意的限制

- **sitemap 只收录本域**。`map.2rtk.com` 的 sitemap 只能放地图页。`2rtk.com` 的首页、教程页、2RTK Server 页需要**在首页站单独生成 sitemap**，否则不会被这个文件收录。
- **页面主体是 JS 渲染**。Google 能执行 JS 并索引到站点名称，百度对 JS 渲染支持较弱。所以 `noscript` 和底部文字条是必要的补充，但不要把关键内容只放在 JS 里。
- **Cesium 加载 6MB**，首屏 LCP 会受影响。SEO 排名里 Core Web Vitals 是因素之一，但地图类应用普遍如此，不必过度优化。

## 六、导航与站点结构

顶部导航已预留 6 个入口，链接通过构建变量配置：

| 导航项 | 默认 URL | 由哪个变量控制 |
|--------|---------|--------------|
| 首页 / 品牌 Logo | `https://2rtk.com/` | `HOME_ORIGIN` |
| 基准站地图（当前页） | `https://map.2rtk.com/` | `SITE_ORIGIN` |
| 搭建教程 | `https://2rtk.com/guide/` | `HOME_ORIGIN` |
| 2RTK Server | `https://2rtk.com/2rtkserver/` | `HOME_ORIGIN` |
| NTRIP Caster 搭建 | `https://2rtk.com/caster/` | `HOME_ORIGIN` |
| 免费测试 | `https://2rtk.com/free-caster/` | `HOME_ORIGIN` |

### 修改导航

编辑 `index.html` 中 `<nav class="site-nav">` 区块：

```html
<a href="__HOME_ORIGIN__/guide/" data-i18n="navGuide">搭建教程</a>
```

- `__HOME_ORIGIN__` 会被替换为首页站域名
- `data-i18n` 指向 `I18N` 里的键名，中英文都会跟着变
- 新增一项时需要**同时**在 `I18N.zh` 和 `I18N.en` 里加 `navXxx`

### 后续页面尚未创建时

导航链接会指向 404。建议要么先创建占位页（哪怕只有一段介绍），要么临时注释掉未上线的项——大量 404 外链会拉低搜索引擎对站点质量的判断。

## 七、构建配置速查

### Cloudflare Pages 设置

```
Build command:    python3 scripts/build.py
Output directory: dist
```

### 环境变量（全部可选）

| 变量 | 作用 | 默认值 |
|------|------|--------|
| `CESIUM_ION_TOKEN` | Ion / Bing 影像 | 空（用公共源） |
| `TIANDITU_TOKEN` | 天地图影像（**必须浏览器端 Key**） | 空 |
| `SITE_ORIGIN` | 地图站域名，用于 canonical / sitemap | `https://map.2rtk.com` |
| `HOME_ORIGIN` | 首页站域名，用于导航链接 | `https://2rtk.com` |

### 本地预览

```bash
python scripts/build.py
cd dist && python -m http.server 8092
# 浏览器打开 http://127.0.0.1:8092/
```

本地预览必须走 `dist/` 目录，不能直接打开根目录的 `index.html`——因为 `__SITE_ORIGIN__` / `__HOME_ORIGIN__` / `__BUILD_ID__` 占位符需要构建时替换。构建脚本带残留校验，漏替换会直接报错退出。

## 八、常见问题

**Q：地球是纯色球，没有影像？**
按顺序排查：① 底部「底图」按钮文本是否为「底图 · 无可用」；② 浏览器控制台是否有 `[2RTK] 图源探测 xxx -> 不可达`；③ 打开底图面板看各源状态。若全部不可达，说明当前网络屏蔽了所有公共瓦片源，此时配一个天地图 Key 即可解决（天地图在国内必定可达）。

**Q：站点位置和底图对不齐？**
检查是否误加了高德/腾讯图源。本项目的 `BASEMAPS` 里只有 WGS84 / CGCS2000 图源，不要手动添加 GCJ-02 源。

**Q：切换语言后按钮文字没变？**
可能是 `data-i18n` 的键在另一个语言对象里缺失，回退成了英文。检查 `I18N.zh` 与 `I18N.en` 的键是否一一对应。

**Q：Cesium 版本还能再升吗？**
`index.html` 里两处版本号（`widgets.css` 的 `<link>`、`CESIUM_BASE_URL`、`Cesium.js` 的 `<script>`）需同步修改。升级前先用 `curl` 确认 `cdn.jsdelivr.net/npm/cesium@<版本>/Build/Cesium/Cesium.js` 返回 200，并检查 `UrlTemplateImageryProvider`、`ImageryLayer.fromProviderAsync` 等 API 是否仍存在。
