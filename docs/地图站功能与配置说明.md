## 一、关于「Cesium 自带的免费图源」

### 结论：内置的底图选择器能用，但内置的图源不够用

CesiumJS 的 Viewer 自带一个底图切换按钮（`baseLayerPicker`），但**它内置的图源列表只有 Cesium Ion 影像 / Bing 影像**，都依赖 Ion token。OSM 需要自己填。

所以本站的做法是：**用 Cesium 自带的那个按钮，把自定义图源注入进去**，不再自己做一套底部按钮 + 弹层。

```js
var viewer = new Cesium.Viewer('cesiumContainer', {
  baseLayerPicker: true,                     // Cesium 自带按钮
  imageryProviderViewModels: VIEW_MODELS,    // 注入自定义图源
  selectedImageryProviderViewModel: VIEW_MODELS[0],
  terrainProviderViewModels: []
});
```

`VIEW_MODELS` 由 `buildBasemapViewModels()` 生成：把 `BASEMAPS` 里每一项包装成 `Cesium.ProviderViewModel`（name / category / iconUrl / creationFunction），图标是内联 SVG data URI，不额外发请求。

### 实测（2026-11，中国大陆网络）：到底谁要 Key

> 判断方法：不要只看 HTTP 200，要**把瓦片下载下来逐张看图**。
> 有些源（尤其 CARTO）无 Key 也会返回 200，但瓦片内容就是一行 `API KEY REQUIRED` 水印。

| 图源 | 免 Key 状态 | 坐标基准 | 说明 |
|------|------------|---------|------|
| **Esri World_Imagery**（`server.arcgisonline.com`） | ✅ 无水印，1~2 秒可达 | WGS84 | 本站默认影像源 |
| **Esri World_Street_Map** | ✅ 无水印，国内可达 | WGS84 | 本站默认街道源 |
| `basemaps.cartocdn.com`（CARTO 街道 / 深色） | ❌ 瓦片是 `API KEY REQUIRED` 水印 | WGS84 | **已从站点移除** |
| `tile.openstreetmap.org` | 国内不可达，海外正常 | WGS84 | 保留，海外兜底 |
| Cesium Ion（Bing 影像） | 需免费 Ion token | WGS84 | 画质最好 |
| 天地图 | 需免费「浏览器端」Key | CGCS2000 | 国内最稳 |
| NASA GIBS Blue Marble | ✅ 免 Key | EPSG:3857 | 静态蓝地球，最高 8 级 |
| 高德 AMap（街道 / 卫星） | ✅ 免 Key，国内极快 | **GCJ-02** | 只能手动选，见下节 |

所以策略是：**默认 Esri（免 Key、无水印、国内可达），有 token 的源排前面做可选升级，NASA 蓝地球兜底，高德只给人手动切。**

### ⚠️ 为什么高德只能「手动选」，不能做默认

高德、腾讯、百度等国内图源使用 **GCJ-02（火星坐标）**，与基准站使用的 WGS84 之间相差 **300~700 米**，而且偏移量随经纬度变化，不是固定平移。

对厘米级定位的 RTK 场景来说，这等于把站点挪到了隔壁街区，覆盖范围圈也会一起偏。

代码里的处理：

```js
{
  id: 'amap-street',
  priority: 20,
  manualOnly: true,   // 不参与自动探测，永远不会被自动选中
  gcj02: true,        // 标记：坐标基准不同
  tooltip: 'AMap 免 Key · 但为 GCJ-02 火星坐标，站点会偏移 300~700 米'
}
```

- 进入底图面板，**用户可以自己切**（墙内网络最快）
- 但自动降级永远不会选它，避免访客在不知情的情况下看到偏移的站点

如果以后要真正"把高德底图摆正"，需要做逐瓦片的 GCJ-02→WGS84 纠偏（按瓦片中心算偏移再重算瓦片索引），属于另一个工程量，目前没做。

### 坐标兼容的图源汇总

- **Esri（影像 / 街道）** — WGS84 / Web Mercator，全球，免 Key
- **Cesium Ion（Bing）** — WGS84 / Web Mercator，全球
- **天地图** — CGCS2000，与 WGS84 差异在厘米级，中国区最优
- **OpenStreetMap** — WGS84 / Web Mercator，全球
- **NASA GIBS** — EPSG:3857，全球
- ❌ 高德 / 腾讯 / 百度 — GCJ-02，只能当"看看路名"的参考层

## 二、多图源自动降级机制

### 图源列表（`BASEMAPS`）

| 展示顺序 | id | 面板名称 | priority | 凭证 | 坐标 |
|---|----|---------|---------|------|------|
| 1 | `esri-imagery` | Esri 影像 | **1** | 无 | WGS84 |
| 2 | `ion` | Bing 影像 | 2 | `CESIUM_ION_TOKEN` | WGS84 |
| 3 | `tianditu` | 天地图影像 | 3 | `TIANDITU_TOKEN` | CGCS2000 |
| 4 | `gibs` | NASA 蓝地球 | 9 | 无 | EPSG:3857 |
| 5 | `esri-street` | Esri 街道 | 5 | 无 | WGS84 |
| 6 | `osm` | OpenStreetMap | 6 | 无 | WGS84 |
| 7 | `amap-street` | 高德街道 | — | 无（手动） | **GCJ-02** |
| 8 | `amap-sat` | 高德卫星 | — | 无（手动） | **GCJ-02** |

- **数组顺序** 决定 Cesium 底图面板里的排列
- **priority** 决定探测完成后自动选谁（数字越小越优先）
- `manualOnly: true` 的源不参与自动探测（高德这两个）
- 缺少凭证的源（`needKey()` 返回 true）不会进面板，避免出现点了没反应的死项

### 工作流程

```
页面加载
  └─ 立即创建 Viewer，首屏挂上 Esri 影像（免 Key，秒出图）
       └─ 并行探测所有图源
            ├─ 无凭证的源跳过
            ├─ 加载一张真实瓦片（z=3），5 秒超时
            ├─ 全部完成后按 priority 选最优可用源
            └─ 与当前源不同 → 自动切换（例如 Esri 被墙时会退到 NASA 蓝地球）
```

探测用的是 `new Image()` 加载真实瓦片，不是 ping 域名——这样能识别「域名通但瓦片 403 / 被墙」的情况。
但它**判断不了瓦片是不是水印图**，所以 CARTO 那种"200 + 水印"的源只能靠人工实测排除。

用户也可以直接点 Cesium 右上角那个地球图标切换底图，面板里按「影像 / 街道」分组，鼠标悬停有每个源的说明。

## 三、数据源按钮（左侧）

| 按钮 | 数据文件 | 颜色 | 说明 |
|------|---------|------|------|
| `2RTK` | `data/2rtk.json` | 青色 | 自己的 Caster（未配置时提示去 `ntrip_servers.ini` 加配置） |
| `CRTK` | `data/France.json` | 品红 | 法国 CRTK 网络 |
| `RTK2` | `data/rtk2go.json` | 橙色 | rtk2go 全球公开源，默认打开 |
| `IGS` | `data/IGSNetwork.json` | 亮绿 | IGS 全球大地测量网，769 站 |

### IGS 数据的结构差异

IGS 的 json 是**以 4 字符站号为键的字典**，字段是 PascalCase：

```json
{ "ABMF00GLP": { "CountryOrRegion": "GLP", "Latitude": "16.262", "Longitude": "-61.528",
                 "Height": "-25.748",
                 "Receiver": { "Name": "SEPT POLARX5", "SatelliteSystem": "GPS+GLO+GAL+BDS+SBAS", ... },
                 "Antenna":  { "Name": "TRM57971.00", "Radome": "NONE", ... } } }
```

和 NTRIP 站点的扁平结构不同，所以 `normalizeIgsStations()` 先把它转平再交给 `addRtkEntities()`：

- 点画得更大（8px，普通站 5px），整球视角也看得见
- **不画覆盖圈**——IGS 是大地测量参考站，不是 RTK 服务，圈 10 公里会误导
- 信息面板用另一套字段（站号 / 接收机 / 天线 / 安装日期）

## 四、卫星图层（TLE）

### 为什么要有本地 TLE 文件

`celestrak.org` 对同一 IP 有下载频率限制，超限直接返回 `403 Forbidden`：

```
Access from IP address x.x.x.x was blocked ...
We have detected excessive downloads ... restored once the excessive downloads have ceased for 2 hours
```

前端如果直连 CelesTrak，访客（或同一出口 IP 的整栋楼 / 整个机房）一旦被限流，
**卫星图层就一颗都画不出来**——这也是之前"卫星不见了"的真实原因。

所以改成：

```
fetch('./data/tle-gnss.txt')     ← 首选，跟站点一起部署，永不 403
   └─ 失败（文件缺失 / 内容为空）→ fetch(CelesTrak 实时接口)
        └─ 再失败 → 控制台警告，站点图层不受影响
```

### 刷新 TLE

```bash
python scripts/fetch_tle.py           # 生成 data/tle-gnss.txt
python scripts/fetch_tle.py --check   # 只检查本地文件是否过期
```

脚本的数据源优先级：

1. **CelesTrak** 官方 GNSS 组（最新最权威）
2. **tle.ivanstanojevic.me**（Space-Track 镜像，按 GPS / GLONASS / GALILEO / BEIDOU / QZS / IRNSS 逐个搜）
3. 都失败 → 保留现有文件，不覆盖

`data/tle-gnss.txt` 已经加进 `.gitignore` 白名单（`!data/tle-gnss.txt`），会随仓库一起部署。
`scheduler.py` 每 6 小时采集完站点数据后会顺带刷新一次 TLE。

### 卫星图层的显示控制

底部控制条有两个独立开关，互不影响：

| 按钮 | 作用 | 实现 |
|------|------|------|
| **隐藏卫星 / 显示卫星** | 整个卫星图层（图标 + 标签）显隐 | 遍历 `entity.isSatellite`，切 `entity.show` |
| **显示卫星标签 / 隐藏卫星标签** | 只控制卫星名称文字 | 切 `entity.label.show` |

- 卫星整体隐藏时，标签按钮会自动置灰（标签开关没有意义）
- 若当时正打开着某颗卫星的信息面板，隐藏卫星会一并把面板收起
- 新建卫星实体时按当前 `satellitesVisible` 状态初始化 `show`，所以先隐藏再等 TLE 加载完，卫星不会自己冒出来

### 卫星为什么不随时间移动

当前实现是**快照式**：页面加载时按 TLE 算一次位置就固定下来。
GNSS 卫星都在 2~3.6 万公里高度，几分钟内位移肉眼看不出来，刷新页面即可更新。

如果要让它动起来，需要把 `viewer.clock.onTick` 里加每个卫星的 `CallbackProperty` 重算 —— 113 颗卫星每帧算一遍，中低端手机会卡，暂时没做。

## 五、天地图 Key 怎么配（重点）

### 当前状态：代码里是空字符串

```js
var TIANDITU_KEY = typeof RUNTIME_CONFIG.tiandituToken === 'string'
  ? RUNTIME_CONFIG.tiandituToken.trim() : '';
```

项目里**没有任何硬编码的天地图 Key**，也**不包含任何小程序相关的 Key**（已全仓库检索确认）。`config.js` 里对应字段是空值：

```js
window.__2RTK_CONFIG = {"cesiumIonToken":"","tiandituToken":"","siteOrigin":"...","homeOrigin":"..."};
```

### 申请时必须选「浏览器端」

这是最容易踩的坑。天地图控制台创建应用时，「应用类型」有三个选项：

| 应用类型 | 能否用于本页面 | 说明 |
|---------|--------------|------|
| **浏览器端** | ✅ 可以 | 唯一可用于网页前端 |
| 服务端 | ❌ 不行 | 会返回 403，只在后端 Python/Node 里能用 |
| 小程序端 | ❌ 不行 | 只对微信小程序域名白名单生效 |

**请单独申请一个「浏览器端」Key**，不要复用小程序那个——小程序 Key 有独立的白名单和配额，混用会导致小程序侧调用失败。

申请地址：<https://console.tianditu.gov.cn/api/key>（个人开发者免费，日配额足够本场景）

### 配置方式

Cloudflare Pages 环境变量里加：

```
TIANDITU_TOKEN = 你的浏览器端Key
```

构建时会写入 `dist/config.js`，不会进入 Git 仓库。

### 不配天地图会怎样

完全不影响使用。页面会自动用 Esri 或 CARTO，只是在中国大陆访问速度可能不如天地图。天地图的定位是**备选加速源**，不是必需项。

## 六、中英双语

### 切换方式

- 右上角、Cesium 自带控件左侧的按钮：中文界面显示 `EN`，英文界面显示 `中文`（位置由 `positionLangSwitch()` 按 `.cesium-viewer-toolbar` 的实际包围盒计算，不写死坐标）
- URL 参数：`?lang=zh` / `?lang=en`（优先级最高，方便搜索引擎区分版本）
- `localStorage` 记住上次选择
- 首次访问按 `navigator.language` 自动判断（`zh*` → 中文，其余 → 英文）

### 页脚说明

页脚固定两行，随语言切换：

- 第一行：`2rtk.com` 的用途（展示免费 RTK 基准站公共资源）+ 免费 NTRIP Caster 测试 + 数据每 6 小时更新
- 第二行：权益声明 —— 站点被收录且不希望展示、或认为权益受影响，联系 `i@jia.im`

底部容器 `bottom-stack` 是 flex 纵向布局，页脚文字换行变高时，上面的控制按钮组会自动被顶上去；
版权署名（`CreditDisplay`）挂在页脚条内部右下角，不再和其它浮层抢位置。

### 翻译范围

| 区域 | 是否翻译 |
|------|---------|
| 顶部导航 | ✅ |
| 底部控制按钮（暂停旋转 / 卫星显隐 / 卫星标签 / 站点标签 / 覆盖范围） | ✅ |
| 数据更新时间信息栏 | ✅ |
| 站点 / 卫星信息框字段名 | ✅ |
| 底部关键词条 | ✅ |
| **左侧数据源按钮（2RTK / CRTK / RTK2）** | ❌ 保持原样 |

左侧数据源按钮按需求**固定不翻译**——这些是 Caster 的专有名称，翻译反而会造成混淆。

### 切换是实时的，不用刷新

Cesium 的 InfoBox（点站点后弹出的面板）只在「选中项发生变化」时重绘，
直接改 `entity.description` 不会刷新已经打开的面板。

所以站点实体在创建时会记住原始数据：

```js
marker._station = station;
marker._stationType = stationType;
```

切换语言时 `refreshStationDescriptions()` 做两件事：

1. 遍历所有实体，用新语言重新生成 `description`
2. 如果当前正有面板打开，先 `selectedEntity = undefined` 再设回去，强制 InfoBox 重绘

卫星面板同理（`buildSatelliteDescription()`）。

### 新增文案

在 `index.html` 的 `I18N.zh` 和 `I18N.en` 两个对象里同时加键，然后调用 `t('key')` 即可。只加一边会导致另一边回退到英文。

## 七、SEO 实现

### 已做的项

| 项 | 位置 | 说明 |
|----|------|------|
| `<title>` | head | 「全球免费 RTK 基准站地图 \| 2RTK NTRIP Caster 基站可视化」，含核心关键词 |
| `meta description` | head | 覆盖 RTK 基准站、NTRIP Caster、GNSS、免费测试等语义 |
| `meta keywords` | head | 现代搜索引擎权重低，但对部分中文引擎仍有参考价值 |
| `canonical` | head | `https://map.2rtk.com/` |
| `hreflang` | head | `zh-CN` / `en` / `x-default`，用 `?lang=` 区分，符合规范 |
| Open Graph | head | 微信、Facebook、Twitter 分享卡片 |
| JSON-LD | head | `Organization` + `WebSite` + `WebApplication`（含 `offers: 0 元`） |
| `<h1>` | body | `sr-only` 隐藏，视觉不影响地图，但给爬虫明确主题 |
| `<noscript>` | body | 完整的中文介绍段落，JS 不被执行时也有内容 |
| 底部关键词条 | body | 默认可见的一行文字，爬虫可读 |
| 顶部导航 | body | 真实 `<a href>` 链接，不是 JS 跳转 |
| `robots.txt` | 构建生成 | `Allow: /` + sitemap 地址 |
| `sitemap.xml` | 构建生成 | 收录地图页 + 5 个内容页，含 `lastmod`，构建时自动更新 |

### 需要注意的限制

- **sitemap 只收录本域**。现在地图页与内容页同属 `SITE_ORIGIN`，`scripts/build.py` 的 `PAGES` 列表即 sitemap 的页面来源，新增页面记得登记，否则不会被收录。
- **页面主体是 JS 渲染**。Google 能执行 JS 并索引到站点名称，百度对 JS 渲染支持较弱。所以 `noscript` 和底部文字条是必要的补充，但不要把关键内容只放在 JS 里。内容页是纯静态 HTML，正好补上这块短板。
- **Cesium 加载 6MB**，首屏 LCP 会受影响。SEO 排名里 Core Web Vitals 是因素之一，但地图类应用普遍如此，不必过度优化。

```
└── test-caster/index.html
```

- 构建时 `site/` 整体复制到 `dist/`，目录名即 URL；每个目录下的 `index.html` 是该页入口。
- 内容页同样支持 `__SITE_ORIGIN__` 与 `__BUILD_ID__` 占位符（用于 canonical / 静态资源版本号），`scripts/build.py` 会逐文件替换并做残留校验。
- 页面内引用样式与脚本一律用绝对路径 `/assets/...`，避免子目录相对路径踩坑。

### 修改导航

导航有两处，必须同步改：

1. `index.html` 的 `<nav class="site-nav">`（地图页，浮在 Cesium 之上）
2. `site/*/index.html` 每页头部的 `<nav class="nav">`（内容页，吸顶）

```html
<a href="/caster/" data-i18n="navCaster">Caster 搭建</a>
```

- 当前页加 `class="is-current" aria-current="page"`
- 地图页的链接带 `data-i18n`，新增项要**同时**在 `I18N.zh` 和 `I18N.en` 里加键；内容页是纯静态中文，不带 `data-i18n`
- 移动端导航是横向滚动条（`overflow-x: auto`），项目多时不会被裁切

### 新增一个内容页

1. 复制任一 `site/<slug>/index.html`
2. 改 `<title>`、`<meta name="description">`、`<link rel="canonical">`、`<h1>`
3. 正文里每个 `<h2>` 都加 `id`，右侧目录会自动生成（`data-toc`）
4. 在 `scripts/build.py` 的 `PAGES` 里加一行（slug + sitemap 权重 + 更新频率）
5. 在 6 个页面的导航与页脚里补链接

## 十、常见问题

**Q：地球是纯色球，没有影像？**
按顺序排查：① 浏览器控制台是否有 `[2RTK] 底图探测 xxx -> 不可达`；② 打开 Cesium 右上角地球图标看面板里还剩哪些源；③ 若底图出现 `API KEY REQUIRED` 水印，说明落到 Esri / CARTO 兜底了。最省事的解决办法是配一个天地图 Key（国内必定可达）或免费 Ion token。

**Q：站点位置和底图对不齐？**
检查是否误加了高德/腾讯图源。本项目的 `BASEMAPS` 里只有 WGS84 / CGCS2000 图源，不要手动添加 GCJ-02 源。

**Q：切换语言后按钮文字没变？**
可能是 `data-i18n` 的键在另一个语言对象里缺失，回退成了英文。检查 `I18N.zh` 与 `I18N.en` 的键是否一一对应。

**Q：Cesium 版本还能再升吗？**
`index.html` 里两处版本号（`widgets.css` 的 `<link>`、`CESIUM_BASE_URL`、`Cesium.js` 的 `<script>`）需同步修改。升级前先用 `curl` 确认 `cdn.jsdelivr.net/npm/cesium@<版本>/Build/Cesium/Cesium.js` 返回 200，并检查 `UrlTemplateImageryProvider`、`ImageryLayer.fromProviderAsync` 等 API 是否仍存在。

**Q：内容页样式丢了 / 右侧目录不显示？**
两种常见原因：① 直接双击打开了 `site/xxx/index.html`，没走构建，`/assets/site.css` 是绝对路径在 `file://` 下解析不到；② 右侧目录由 `site.js` 扫描 `.prose h2[id]` 生成，忘了给 `<h2>` 加 `id` 就是空的。

**Q：新加的页面在 sitemap 里找不到？**
`scripts/build.py` 顶部的 `PAGES` 列表是唯一来源（slug + 权重 + 频率），只建目录不加登记就不会进 sitemap。
