# NTRIP Caster 隧道管理验证教程（最小可行验证）

> 目标：用最小成本验证「国内服务器上的 caster 后台，能否通过 Cloudflare Tunnel 从外网正常登录管理」。
>
> 验证思路分两步：
> 1. **第一步（5分钟，零成本）**：用临时隧道 + 假网页服务，先确认隧道原理跑通
> 2. **第二步（正式）**：装 caster + 正式隧道 + 域名，验证后台真正能管理

---

## 第一步：验证隧道原理（最快，5分钟，零配置）

这一步**不需要域名、不需要 caster、不需要备案**，用 Cloudflare 自带的临时隧道功能，几分钟确认「隧道能通」。

### 1.1 买服务器（国内云服务器）

推荐：阿里云/腾讯云 **轻量应用服务器**，最低配即可（1核1G 约 ¥30-50/月）。

**关键要求**：
- 必须**有独立公网 IP**（轻量服务器默认有）
- 系统选 **Ubuntu 22.04 或 Debian 12**（下面命令按这个写）

> 买的时候不需要买域名，也不需要备案，因为这一步用临时隧道。

### 1.2 登录服务器

```bash
ssh root@你的服务器公网IP
```

### 1.3 下载 cloudflared

```bash
# 下载（amd64 架构，绝大多数服务器都是）
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
sudo mv cloudflared-linux-amd64 /usr/local/bin/cloudflared
sudo chmod +x /usr/local/bin/cloudflared

# 验证
cloudflared --version
```

> 如果你的服务器是 ARM 架构（少见），把 `amd64` 换成 `arm64`。

### 1.4 起一个假网页服务（模拟 5757 后台）

```bash
# 用一个最简单的 Python 网页服务，模拟 caster 后台
echo '<h1>Caster 后台（模拟）</h1><p>隧道已打通！</p>' > /tmp/index.html
cd /tmp && nohup python3 -m http.server 5757 --bind 127.0.0.1 > /dev/null 2>&1 &
```

> 注意 `--bind 127.0.0.1`：只监听本地，不对外。这正是「免开端口」的关键。

### 1.5 启动临时隧道（零配置，无需登录）

```bash
cloudflared tunnel --url http://127.0.0.1:5757
```

启动后，屏幕上会输出一个 **`https://xxxx.trycloudflare.com`** 的临时地址。

### 1.6 验证

用**你的手机（用 4G/5G 流量，别用服务器所在 WiFi）**或另一台设备，浏览器打开那个 `trycloudflare.com` 地址。

- ✅ 能看到「Caster 后台（模拟）隧道已打通」→ **隧道原理验证成功**
- ❌ 打不开 → 检查服务器能否正常访问外网（`curl https://cloudflare.com`）

> 这一步通过，就说明「国内服务器 → Cloudflare 隧道 → 外网访问」这条路**完全可行，且不需要开任何端口、不需要备案**。

## 第二步：正式验证 caster 后台管理（需要域名）

第一步通过后，进入正式环节：装真正的 caster，用**你自己的域名 + 正式隧道**，验证后台登录管理。

### 2.1 前提准备

- [ ] 一个域名（2rtk.com，任意域名商买，¥50-80/年）
- [ ] 域名 NS 托管到 Cloudflare（在 Cloudflare 添加站点，按提示改域名商的 NS）
- [ ] Cloudflare 账号

### 2.2 装 caster

根据你选的 caster 软件，安装后确认：

```bash
# 确认 caster 后台在本地能访问（关键前提）
curl http://127.0.0.1:5757
# 应返回后台 HTML 或跳转登录页
```

> 如果这一步 curl 都访问不到，说明 caster 没装好，先解决这个再往下。

### 2.3 登录 Cloudflare 并授权

```bash
cloudflared tunnel login
# 浏览器打开输出的 URL，选你的域名（2rtk.com）授权
```

### 2.4 创建正式隧道

```bash
cloudflared tunnel create caster
# 记下输出的 Tunnel ID（一长串 UUID）
```

### 2.5 配置隧道

编辑 `~/.cloudflared/config.yml`：

```yaml
tunnel: <你的 Tunnel ID>
credentials-file: /root/.cloudflared/<你的 Tunnel ID>.json

ingress:
  - hostname: caster.2rtk.com
    service: http://127.0.0.1:5757
  - service: http_status:404
```

### 2.6 配置 DNS

```bash
cloudflared tunnel route dns caster caster.2rtk.com
```

### 2.7 装成系统服务（开机自启）

```bash
sudo cloudflared service install
sudo systemctl enable cloudflared
sudo systemctl start cloudflared
sudo systemctl status cloudflared   # 应显示 active (running)
```

### 2.8 验证后台管理

浏览器访问 `https://caster.2rtk.com`：

- ✅ 能看到 caster 后台登录页 → 登录 → 能加挂载点、改用户 → **验证成功**
- ❌ 打不开 → 按下面排查

---

## 三、常见问题排查

| 现象 | 原因 | 解法 |
|------|------|------|
| 临时隧道打不开 | 服务器访问不了外网 | `curl https://cloudflare.com` 测试 |
| caster.2rtk.com 打不开 | DNS 没生效 | 等几分钟，或 `dig caster.2rtk.com` 查解析 |
| 隧道 active 但页面 502 | ingress 配的 service 地址不对 | 确认 caster 监听 `127.0.0.1:5757` |
| cloudflared 报错连不上 | 网络/防火墙 | 确认出站 443 端口可用（默认都行） |

---

## 四、验证成功后的安全加固（别忘了）

隧道通了之后，`caster.2rtk.com` 是**公开可访问**的，任何人打开都能看到后台。必须加访问控制：

### 方案 A：Cloudflare Access（推荐）

Cloudflare Zero Trust → Access → 给 `caster.2rtk.com` 加策略，只允许你自己邮箱登录。

### 方案 B：临时措施

在 caster 后台设强密码；或验证完先 `systemctl stop cloudflared` 停掉隧道，等正式上线再配 Access。

---

## 五、验证结论判据

完成两步后，你就能回答最初的问题：

- ✅ **隧道能正常管理后台** → 方案可行，继续走完整部署（首页/地图/采集器）
- ⚠️ **隧道通但后台有问题** → 是 caster 本身的问题，不是隧道的问题
- ❌ **隧道都不通** → 服务器网络/防火墙问题，先解决连通性
