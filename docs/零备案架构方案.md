# 2RTK 完整架构方案与部署教程（Cloudflare 全家桶 + 国内 caster）

> 最终定稿架构。一句话总结：
> **caster 放国内服务器 → Cloudflare Tunnel 透传管理页到 caster.2rtk.com；首页和地图放 Cloudflare Pages；采集器用 git push 喂数据给地图站。全程免备案、零端口暴露。**

---

## 一、整体架构

```
┌────────────────────────────────────────────────────────────┐
│  Cloudflare（免费，境外，免备案）                             │
│                                                            │
│  ┌─ 2rtk.com        → 首页（VitePress 静态站）   Cloudflare Pages │
│  ├─ map.2rtk.com    → 地图站（Cesium）          Cloudflare Pages │
│  └─ caster.2rtk.com → caster 管理后台            Cloudflare Tunnel│
└────────────────────────────────────────────────────────────┘
                    ▲                    ▲
                    │ git push 数据       │ 加密隧道（服务器主动向外连）
                    │                    │
┌────────────────────────────────────────────────────────────┐
│  国内服务器（1核1G，直连 IP，不备案）                         │
│                                                            │
│  ├─ NTRIP Caster   → 2101 数据流（对外开放，RTK 接收机连）    │
│  ├─ Caster 管理后台 → 127.0.0.1:5757（只监听本地，经隧道出去） │
│  └─ lary.py 采集器 → 每 6 小时抓数据 → git push              │
└────────────────────────────────────────────────────────────┘
```

### 数据与访问流向

| 角色 | 访问什么 | 走哪条路 |
|------|---------|---------|
| 访客（学习） | 2rtk.com 首页 | Cloudflare Pages（CDN 加速） |
| 访客（看覆盖） | map.2rtk.com 地图 | Cloudflare Pages |
| 你（管理 caster） | caster.2rtk.com | Cloudflare Tunnel（免备案、免开端口） |
| RTK 接收机（测试） | 服务器IP:2101 | TCP 直连（不经网页） |
| 采集器 → 地图数据 | data/*.json | git push → Pages 自动重建 |

---

## 二、核心优势（为什么这么搭）

| 诉求 | 方案 | 效果 |
|------|------|------|
| 不想备案 | 网页全放 Cloudflare（境外），caster 只走 IP+非标端口 | ✅ 全程免备案 |
| 远程管理 caster | Tunnel 把 5757 透传到 caster.2rtk.com | ✅ 任何地方登录管理，免备案+免开端口+自动HTTPS |
| 页面省钱 | 首页+地图放 Pages | ✅ ¥0 托管费，无限流量 |
| 数据自动更新 | 采集器 git push → Pages 自动重建 | ✅ 地图每 6 小时自动刷新 |

## 三、完整部署教程

### 阶段 A：GitHub 仓库（承载源码 + 数据）

**A1. 本地初始化 git 仓库**

```bash
cd E:/2rtkcom

git init

# 创建 .gitignore（关键：排除敏感文件）
cat > .gitignore <<'EOF'
__pycache__/
*.pyc
.DS_Store
ntrip_servers.ini       # 含 caster 账号密码，绝不能上传
data/meta.json          # 运行时生成，可选排除
EOF

git add .
git commit -m "init: 2RTK 地图站与首页"
```

> ⚠️ **`ntrip_servers.ini` 必须排除**：里面有 caster 账号密码，一旦推到公开仓库就泄露了。它只存在服务器上。

**A2. 推送到 GitHub**

```bash
git remote add origin https://github.com/你的用户名/2rtk-site.git
git branch -M main
git push -u origin main
```

**A3. 建议的仓库结构（monorepo，一个仓库承载两站）**

```
2rtk-site/
├── index.html            # 地图站入口（Cloudflare Pages 项目1 指向根目录）
├── lary.py               # 采集器（只在服务器运行，不必上传，但可留作版本管理）
├── scheduler.py
├── data/                 # 采集数据（git push 的来源）
│   ├── rtk2go.json
│   ├── IGSNetwork.json
│   └── ...
├── images/
└── site/                 # VitePress 首页源码（Cloudflare Pages 项目2 指向此目录）
    ├── package.json
    ├── docs/
    └── .vitepress/
```

### 阶段 B：Cloudflare Pages 部署地图站

**B1.** Cloudflare 控制台 → Workers & Pages → Create → Pages → Connect to Git → 选 `2rtk-site` 仓库。

**B2.** 构建配置（地图站是纯静态，无需构建）：

| 配置项 | 值 |
|--------|-----|
| Production branch | `main` |
| Build command | 留空 |
| Build output directory | 留空（用根目录） |

**B3.** 绑定域名：Pages 项目 → Custom domains → 添加 `map.2rtk.com`。

**B4.** DNS：域名 `2rtk.com` 的 NS 托管到 Cloudflare，按提示添加记录。

### 阶段 C：VitePress 首页部署到 Cloudflare Pages

**C1.** 本地初始化 VitePress：

```bash
mkdir site && cd site
npm create vitepress@latest .
# 选择：简体中文，其余默认
```

**C2.** 定制首页（三大入口 + 带货 + 捐赠）：
- hero 区三张卡片：**学习教程** / **地图查看** / **免费 caster 测试**
- 「免费 caster 测试」卡片写明 `服务器IP:2101` 连接信息
- 页脚捐赠二维码（微信/支付宝）
- 侧边栏/文章末尾带货卡片（办卡、天线 → 淘宝联盟）

**C3.** 本地构建测试：

```bash
npm run build   # 生成 site/.vitepress/dist
```

**C4.** 新建第二个 Pages 项目（指向同一仓库的 `site/` 子目录）：

| 配置项 | 值 |
|--------|-----|
| Root directory | `site` |
| Build command | `npm install && npm run build` |
| Build output directory | `.vitepress/dist` |

**C5.** 绑定域名 `2rtk.com`。

### 阶段 D：国内服务器部署 caster + 采集器

**D1.** 上传程序：

```bash
# 本地执行，上传到服务器
scp -r /path/to/ntripcaster/* user@服务器IP:/opt/ntripcaster/
scp lary.py scheduler.py ntrip_servers.ini user@服务器IP:/opt/2rtk-collector/
```

**D2.** 配置 caster：
- 数据流端口 `2101`（对外）
- 管理端口 `5757` 监听 `127.0.0.1`（**只监听本地，不对外**，后面经 Tunnel 出去）

```bash
# 确认 5757 只监听本地
ss -tlnp | grep 5757   # 应显示 127.0.0.1:5757，而不是 0.0.0.0:5757
```

**D3.** 配置采集器：

```bash
cd /opt/2rtk-collector
pip3 install requests
# 编辑 ntrip_servers.ini，把 [2rtk] 段填上你 caster 的 2101 账号密码，enabled=true
```

**D4.** 采集 + 推送脚本 `collect_and_push.sh`：

```bash
#!/bin/bash
set -e
cd /opt/2rtk-collector
python3 scheduler.py --once || true

# 同步数据到 git 仓库并推送
cd /opt/2rtk-site
cp /opt/2rtk-collector/data/*.json data/
git add data/
git commit -m "auto: update data $(date '+%Y-%m-%d %H:%M')" || true
git push origin main
```

**D5.** git 免密推送（用 PAT）：

```bash
cd /opt/2rtk-site
git remote set-url origin https://<你的PAT>@github.com/你的用户名/2rtk-site.git
```

**D6.** crontab 每 6 小时：

```bash
chmod +x collect_and_push.sh
crontab -e
# 添加：
0 */6 * * * /opt/2rtk-collector/collect_and_push.sh >> /var/log/2rtk.log 2>&1
```

---

### 阶段 E：Cloudflare Tunnel 透传 caster 管理页（重点）

**E1.** 下载安装 cloudflared：

```bash
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
sudo mv cloudflared-linux-amd64 /usr/local/bin/cloudflared
sudo chmod +x /usr/local/bin/cloudflared
cloudflared --version
```

**E2.** 登录授权：

```bash
cloudflared tunnel login
# 浏览器打开输出的 URL，选域名 2rtk.com 授权
```

**E3.** 创建隧道：

```bash
cloudflared tunnel create caster
# 记下输出的 Tunnel ID（UUID）
```

**E4.** 配置 `~/.cloudflared/config.yml`：

```yaml
tunnel: <Tunnel ID>
credentials-file: /root/.cloudflared/<Tunnel ID>.json

ingress:
  - hostname: caster.2rtk.com
    service: http://127.0.0.1:5757
  - service: http_status:404
```

> 注意：`service: http://127.0.0.1:5757` 指向服务器本地回环地址，所以 5757 只需监听 127.0.0.1，**无需对公网开放**。

**E5.** 配置 DNS：

```bash
cloudflared tunnel route dns caster caster.2rtk.com
```

**E6.** 装成系统服务：

```bash
sudo cloudflared service install
sudo systemctl enable cloudflared
sudo systemctl start cloudflared
sudo systemctl status cloudflared
```

**E7.** 验证：浏览器访问 `https://caster.2rtk.com`，应出现 caster 后台登录页。

### 阶段 F：安全加固（必做）

隧道把后台暴露到公网域名了，必须加访问控制，否则任何人都能登录你的 caster 后台。

**方案 A：Cloudflare Access（推荐，免费）**

Cloudflare Zero Trust → Access → 给 `caster.2rtk.com` 加策略：
- 只允许你自己邮箱登录（Google/GitHub/邮箱 OTP）
- 访问时先过 Cloudflare 登录页，再到 caster 后台

**方案 B：区分管理员 vs 测试访客**

| 角色 | 访问 | 权限 |
|------|------|------|
| 你（管理员） | caster.2rtk.com | 全部（加挂载点、改用户） |
| 访客（测试） | 服务器IP:2101 | 只读：用测试账号连数据流 |

**不要**把完整后台开放给所有访客（否则别人能删你的挂载点、改用户）。

## 四、安全组 / 端口配置（云控制台）

| 端口 | 用途 | 开放策略 |
|------|------|---------|
| 22 | SSH | 仅你自己 IP |
| 2101 | NTRIP 数据流 | 0.0.0.0/0（对外开放，RTK 接收机要连） |
| 5757 | 管理后台 | **不开放**（只监听 127.0.0.1，经 Tunnel 出去） |

> 关键点：**5757 不需要在安全组开放任何入站规则**，因为 Tunnel 是服务器主动向外连 Cloudflare，Cloudflare 再转发进来。这比直接暴露 5757 安全得多。

## 七、风险与注意点

1. **`ntrip_servers.ini` 严禁进 git**：含 caster 账号密码。
2. **5757 只监听 127.0.0.1**：不要 `0.0.0.0`，否则公网能直接扫到。
3. **2101 数据流是明文**：公测用只读测试账号，别用管理账号。
4. **Tunnel 依赖 cloudflared 进程存活**：已配 systemd 自启，崩溃会自动重启。
5. **带宽**：RTK 数据流持续传输，轻量服务器默认 3-5M 够几十用户，更多要升带宽。
