NTRIP Caster 搭建与使用

Caster 是整条链路的「中转站」：基站把 RTCM 推上来，流动站按挂载点把流拉下去，中间由它做鉴权、转发和源表公告。 这一页用开源的 BKG NtripCaster，在 1 核 1G 的 VPS 上从零搭起，配好源表和账号，最后用 curl 和流动站验证。

BKG NtripCaster NTRIP 2.0 Ubuntu / Debian TCP 2101

Caster 到底在干什么

NTRIP 协议里有三个角色，很容易记混：

Server（源）基站侧，主动推
占用 1 个上行连接
→
Caster（中枢）收 1 份，发 N 份
鉴权 + 源表
→
Client（客户端）流动站侧，主动拉
按挂载点选流

Caster 具体做四件事：

  • 接收：验证源的密码，把某一路 RTCM 流绑定到一个挂载点（mountpoint）。
  • 分发：一路流可以同时发给几十上百个客户端，基站上行带宽只花一份。
  • 鉴权：每个挂载点可以指定哪些用户名/密码能拉，防止别人白嫖你的基站。
  • 公告：维护源表（sourcetable），告诉所有客户端「我这里有哪些流、在哪、什么格式、什么电文」。

所以它的负载很轻——几十路源、几百个客户端，1 核 1G 的机器绰绰有余，瓶颈永远在带宽和网络质量上。

什么时候值得自己搭

场景建议

数据不能公开（厂区、矿区、项目）必须自己搭，公共 Caster 都是公开源表
要做中继、把别人的流转发进来自己搭，用 relay 把多个上游汇聚成一张源表

服务器准备

  • 配置：1 核 1G、10 GB 硬盘足够；带宽按「每路 1～3 KB/s × 客户端数」估。
  • 系统：Ubuntu 22.04 / Debian 12 都行，本页命令以 Ubuntu 为例。
  • 公网 IP：必须有固定公网地址，家宽没有公网 IP 时用 VPS 或内网穿透。
  • 域名：caster.example.com 解析到该 IP。Caster 的 server_name 必须填域名，不能填 IP。
  • 端口：云厂商安全组 + 系统防火墙都要放行 2101/tcp。
  • 合规：国内服务器对外提供服务的域名需要备案，纯 IP + 非 80/443 端口通常无此要求，但按当地政策确认。

放行端口

shell · 系统防火墙
# ufw（Ubuntu 默认）
sudo ufw allow 22/tcp
sudo ufw allow 2101/tcp
sudo ufw enable

# 如果用的是 firewalld
sudo firewall-cmd --permanent --add-port=2101/tcp
sudo firewall-cmd --reload

编译安装 BKG NtripCaster

源码包由德国联邦制图与大地测量局（BKG）发布，在 RTCM 官方的 NTRIP 页面可以找到 ntripcaster-2.x.x.tar.gz；GitHub 上也有多个可直接编译的镜像仓库。

shell · 编译三步
# 1. 装编译依赖
sudo apt update
sudo apt install -y build-essential

# 2. 解压源码（换成你下载的版本号）
tar xf ntripcaster-2.0.4x.tar.gz
cd ntripcaster-2.0.4x

# 3. 配置、编译、安装
./configure
make
sudo make install

默认安装到 /usr/local/ntripcaster，配置文件在 conf/ 下， 日志在 logs/ 下。安装完先把模板复制成正式配置：

shell · 初始化配置
cd /usr/local/ntripcaster/conf
sudo cp ntripcaster.conf.dist ntripcaster.conf
sudo cp sourcetable.dat.dist sourcetable.dat
ls -l

不想折腾编译？社区有打包好的 Docker 镜像，把 conf/ 挂载进容器、映射 2101 端口即可， 配置方式与下面完全一致。适合只想改配置、不想装编译环境的场景。

配置 ntripcaster.conf

这是主配置，绝大部分坑都出在这里。逐项对照改：

配置项填什么说明
location机房或城市仅元信息，出现在源表里
rp_email你的邮箱对外公示的联系方式，建议填真邮箱
server_urlhttp://caster.example.com源表里给出的主页地址
server_namecaster.example.com必须是能解析到本机的域名，填 IP 会启动失败或行为异常
port 21012101NTRIP 标准端口。同时保留 #port 80 注释，别开 80 抢 Web 服务
encoder_password一串强密码所有源（基站）推流时用的密码。老版本没有源用户名，随便填
max_clients500总连接数上限，按带宽估，别设成天文数字
max_sources40允许的源路数上限
logdir / logfile/usr/local/ntripcaster/logs排错全靠它，权限要允许 caster 进程写入
/MOUNT:user:pass见下每个挂载点允许哪些客户端拉流

访问控制：一行一个挂载点

格式是 /挂载点:用户名:密码,用户名:密码，多个用户用逗号分隔：

ntripcaster.conf · 片段
# 只有 alice、bob 两个账号能拉 BASE01 这路流
/BASE01:alice:str0ngPass,bob:anotherPass

# 不写用户名密码 = 任何人可拉（公开流）
/PUBLIC01

挂载点名区分大小写。base01、BASE01、Base01 是三个不同的流。 定好之后基站、源表、手簿三处必须完全一致。

配置 sourcetable.dat（源表）

源表是 Caster 对外公示的「菜单」。客户端连上 2101 端口后，第一件事就是读它。 文件由若干行记录组成，一行一个 ; 分隔字段：

sourcetable.dat · 两台基站
# CAS 行：描述这个 Caster 自己
CAS;caster.example.com;2101;2RTK-Test;2RTK;0;CHN;31.23;121.47;http://caster.example.com

# STR 行：一行一个挂载点
STR;BASE01;Shanghai-Pudong;RTCM 3.3;1005(10),1074(1),1084(1),1094(1),1124(1),1033(30);2;GPS+GLO+GAL+BDS;2RTK;CHN;31.23;121.47;0;0;u-blox F9P;none;B;N;4000;
STR;BASE02;Suzhou-Industrial;RTCM 3.3;1005(10),1077(1),1087(1),1097(1),1127(1),1033(30);2;GPS+GLO+GAL+BDS;2RTK;CHN;31.30;120.60;0;0;Septentrio Mosaic;none;B;N;8000;

STR 行字段含义

#字段示例说明
1记录类型STR固定写 STR
2挂载点BASE01客户端拉流用的名字
3标识 / 地名Shanghai-Pudong给人看的描述
4格式RTCM 3.3RTCM 2.3 / 3.0 / 3.2 / 3.3
5电文明细1005(10),1074(1)编号(间隔秒)，直接影响客户端能否匹配
6载波20=无 1=L1 2=L1+L2
7星座GPS+GLO+GAL+BDS告诉客户端有哪些系统
8网络名2RTK自定义
9国家CHN三位国家代码
10纬度31.23十进制度
11经度121.47十进制度
12NMEA0是否要求客户端发 GGA
13解类型00=单点 1=固定 2=浮动
14生成设备u-blox F9P接收机型号
15压缩none一般不用压缩
16鉴权BB=Basic，N=不需要
17收费NN=免费 Y=收费
18比特率4000bps，影响客户端预判带宽
19备注空可留空

源表手写容易错。多一个分号、少一个字段，客户端可能直接解析失败或者干脆不显示这路流。 改完一定用 curl 把源表拉下来，肉眼核对你那几行。

启动与自检

shell · 启动
# 官方建议在 bin 目录下运行，让它能找到 conf/
cd /usr/local/ntripcaster/bin
sudo ./ntripcaster

# 另开一个终端，拉源表自检
curl http://caster.example.com:2101/

返回内容里能看到 CAS; 开头的一行和你的每一条 STR;，说明服务正常。 返回 HTTP/1.1 404 或直接超时，就按下面顺序查：

  1. 进程是否还活着（ps aux | grep ntripcaster）。
  2. 日志（/usr/local/ntripcaster/logs/ntripcaster.log）里有没有报错。
  3. 安全组 / 防火墙是否放行 2101。
  4. server_name 是不是写成了 IP。

用 systemd 托管

/etc/systemd/system/ntripcaster.service
[Unit]
Description=NTRIP Caster
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/usr/local/ntripcaster/bin
ExecStart=/usr/local/ntripcaster/bin/ntripcaster
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
shell · 启用
sudo systemctl daemon-reload
sudo systemctl enable --now ntripcaster
sudo systemctl status ntripcaster --no-pager

让数据流进来

Caster 起来只是空壳，源表里的挂载点要真的有源推上来，才会变成「可用」。 基站侧把 RTCM 推到 caster.example.com:2101/挂载点，密码用 encoder_password。 具体推流配置见 RTK 基站搭建。

想先验证链路通不通，可以用 RTKLIB 把一路现成的公共流中继到自己的 Caster 里：

shell · 中继测试
# 从公共源拉一路流，转推到自己的 Caster
str2str -in  "ntrip://user:pass@rtk2go.com:2101/SOME_MOUNT" \
        -out "ntrips://:你的encoder_password@caster.example.com:2101/BASE01"

推上去后再拉一次源表，你会在日志里看到 source connected 一类的记录，挂载点状态变为活跃。

流动站怎么连

手簿 / App / 接收机里选 NTRIP，四项参数：

Caster 地址
caster.example.com
端口
2101
挂载点
BASE01
用户名 / 密码
ntripcaster.conf 里 /BASE01 那一行配的账号

客户端连上后会收到 ICY 200 OK 或 HTTP/1.1 200 OK（取决于 NTRIP 版本），随后就是一串二进制 RTCM。 如果连上了但久久不出固定解，八成是电文不匹配，回头核对源表里第 5 个字段。

安全加固清单

  • 改默认密码：encoder_password 一定要换，模板里的示例密码等于没有密码。
  • 最小开放：只放行 2101，别把 SSH 和数据库一起暴露。
  • 账号隔离：一个客户一个账号，出问题能单独封禁。
  • 限流：给 max_clients 设合理上限，防止被当成免费 CDN 刷。
  • 封禁名单：新版本支持 IP 黑名单，遭到滥用时直接拉黑。
  • 备份：conf/ 整个目录纳入备份，换机器 5 分钟能复活。
  • 监控：定时 curl 源表 + 检查源是否在线，异常发通知。

需要加密？NTRIP 本身是明文 HTTP。要上 TLS，通常用 Nginx 的 stream 模块在 443 端口做四层转发到本机 2101， 证书用 Let's Encrypt。注意很多老手簿不支持 TLS，加了之后兼容性会变差。
