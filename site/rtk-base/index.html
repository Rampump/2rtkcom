实战教程

用 2RTK Server 搭建自己的 RTK 基站

一台支持 RTCM 输出的接收机、一根靠谱的天线、一个稳的坐标，再加上 2RTK Server 做分发， 你就能在自己家门口得到一块稳定的厘米级区域。这一页按实际施工顺序走：选址 → 硬件 → 坐标 → 电文 → 推流 → 验证 → 运维。

2-4 小时施工 RTCM 3.x NTRIP 10 km 覆盖

先选路线：三种玩法

① 推给 2RTK Server

本站自建的 Caster，填四个参数就能推流。适合想给自己或小团队用、又不想维护服务器的场景。

② 推给公共 Caster

rtk2go 之类的免费公共平台。零成本，但数据必须公开，且不接受商业用途。

③ 自己搭 Caster

多基站、私有数据、要给一队人用，就在 VPS 上自己跑一个。见 Caster 搭建。

这一页走第 ① 条路线。基站本身的施工方式三种都一样，只差最后「往哪推」。

选址：决定成败的一半

  • 天空视野：以天线为中心，10°～15° 高度角以上尽量无遮挡。北半球注意南向天空。
  • 远离反射面：大水面、玻璃幕墙、彩钢瓦屋顶、金属货架都会制造多路径。天线尽量比周围高出 1 米以上。
  • 远离干扰源：大功率电台、雷达、逆变器、劣质 LED 电源都可能抬升噪底。
  • 稳固：立杆直径够、底部固定牢、加三向拉线。风一吹就晃的杆子，用手簿能看出坐标在跳。
  • 可维护：留出检修空间，能断电重启、能换 SIM 卡。

不要装在阳台栏杆或空调外机上。金属结构和震动是多路径与周跳的主要来源， 看起来「能看到天」，实际固定率会很差。

基站坐标：这一步错了全盘皆错

基准站的坐标误差会 100% 传递给流动站。基站坐标偏 30 厘米，你用这台基站测出来的每一根桩都偏 30 厘米。 所以坐标绝不能靠接收机自己单点算一下就用。

方法 A：静态观测 + PPP（推荐，无已知点也能做）

  1. 天线固定好，连续观测 2～4 小时（越长越好），采样间隔 30 s，记录 RINEX 观测文件。
  2. 把 RINEX 上传到免费 PPP 服务（如加拿大 NRCan 的 CSRS-PPP、美国 OPUS、武汉大学 PPP 服务）。
  3. 拿到 ITRF 框架下的精确坐标，误差可到 1～3 厘米。
  4. 把结果按需转换到当地坐标系（国内工程常用 CGCS2000）。

注意框架与历元：PPP 给的是 ITRF20xx 某一历元的坐标， 和 CGCS2000 之间差几厘米量级，做一般工程可忽略，做控制网联测则要统一。

方法 B：与已知 CORS 做同步静态基线（相对精度最高）

附近有可靠的 CORS 或城市控制点时，同步观测 1 小时以上，用商业软件或 RTKLIB 做基线解算。 这条路线拿到的是「相对于该控制网」的坐标，做本地工程最合适。

方法 C：单点长时间平均（只适合相对定位）

让接收机在一个点上连续跑 24 小时，把单点解平均。这样能消掉一部分随机误差， 但绝对精度仍然只有米级。只有在「只关心相对位置、不关心绝对坐标」时才这么干。

别忘了天线高

无论用哪种方法，都要记录天线参考点（ARP）到标石/测站标记的高度， 并在接收机里正确填写。斜高请绕天线 120° 量三次取平均，误差控制在 1 毫米内。 输入坐标时也要分清：填的是天线相位中心还是标石，两者差一个天线高。

配置接收机：输出哪些 RTCM

目标只有一个：让 Caster 上有一路完整、连续、能被流动站直接用的 RTCM 3 流。通用配置如下：

电文间隔作用必需性
100510 s基站坐标（ECEF，不含天线高）必需
100610 s基站坐标 + 天线高（二选一）可选
1074 / 1084 / 1094 / 11241 sGPS / GLONASS / Galileo / 北斗 MSM4 观测必需
1077 / 1087 / 1097 / 11271 s同上，MSM7（含信噪比，精度更好、带宽更高）二选一
103330 s接收机与天线型号描述建议
12301 sGLONASS 码相位偏差用 GLO 时必需

其他设置：

  • 观测频率：基站 1 Hz 足够；流动站 1～5 Hz 按需要。
  • 星座：GPS + 北斗 + GLONASS + Galileo 全开，卫星数越多固定越快。
  • 模式：设为「基站 / Base / Fixed」并填入上一步解算出的坐标，不要用「平均位置」。
  • 串口：USB 直连一般 115200 或 921600，确保不丢包。

带宽估算：四系统 MSM4 @1 Hz 大约 1 KB/s（一个月约 2.5～3 GB）； MSM7 约 2～3 KB/s（一个月 6～8 GB）。用 4G 卡长期跑，记得按这个量选套餐。

推流到 2RTK Server

2RTK Server 是本站自建的 NTRIP Caster，用来把基站数据分发给流动站。 先在控制台创建一个属于你的挂载点（mountpoint），拿到账号密码，然后用下面任一方式推送。

方式一：接收机内置 NTRIP Server（最简单）

测绘型接收机一般在 Web 界面里有「NTRIP 推流 / NTRIP Server / 数据转发」页面， 填入上面五个参数、勾选自动重连即可。设置完看一眼状态灯或日志，出现「已连接 / 发送中」就成功了。

方式二：树莓派或路由器用 RTKLIB 转发

接收机只能吐串口、或者你想在中间做一层缓冲时，用 RTKLIB 的 str2str 把串口流推到 Caster：

shell · 串口 → NTRIP Caster
# -in  串口读入，115200 波特率，1 Hz，强制按 rtcm3 解析
# -out 推到 Caster，格式：ntrips://用户名:密码@主机:端口/挂载点
str2str -in  serial://ttyACM0:115200:1#rtcm3 \
        -out "ntrips://用户名:密码@2rtk.com:2101/你的挂载点"

版本差异：较早的 RTKLIB 只支持 ntrips://:密码@主机:端口/挂载点（不带用户名）。 如果报协议错误，先去掉用户名试一次。

让它开机自启，最简单的办法是 systemd：

/etc/systemd/system/rtk-push.service
[Unit]
Description=Push RTCM to 2RTK Server
After=network-online.target

[Service]
ExecStart=/usr/local/bin/str2str -in serial://ttyACM0:115200:1#rtcm3 -out "ntrips://用户名:密码@2rtk.com:2101/你的挂载点"
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target

验证：三看一听

  1. 看源表

    Caster 会把所有挂载点列在源表里。用浏览器或 curl 访问 http://2rtk.com:2101/， 搜你的挂载点。出现 STR;你的挂载点;… 这一行，说明 Caster 已经收到你的流。

  2. 看电文

    用 RTKLIB 的 strsvr 或 str2str 把流拉到本地存成文件， 确认 1005 和观测电文都在，间隔正常、没有大段空洞。

  3. 看地图

    回到 基准站地图，如果你的挂载点已被收录，会以站点形式出现。 地图每 6 小时刷新一次，刚建好的站点不会立刻显示。

  4. 听流动站

    最终判据只有一个：流动站能不能稳定拿到 Fixed。 在基线上取 3 个点复测，平面较差应在 2 厘米以内。

流动站怎么用

手簿、App 或接收机 Web 界面里选「NTRIP / 网络 RTK」，填四项：

字段填写
Caster IP / 域名2rtk.com
端口2101
挂载点你创建的站点名（大小写敏感）
用户名 / 密码与推流时一致或单独分配

连上后注意两件事：一是天线高要按流动站自己的杆高填对； 二是等固定解稳定 10 秒以上再开始测，别抢那一两秒的假固定。

长期运维

  • 断电自恢复：接收机、路由器、树莓派全部设成上电自启；路由器加定时重启。
  • 断线重连：str2str 用 Restart=always；接收机内置推流勾选自动重连。
  • 坐标复核：板块每年移动几厘米，高精度应用建议每年复测一次。
  • 天线检查：台风、大雪后检查立杆垂直度和接头进水。
  • 监控：至少做到「掉线能收到通知」。可以定时 curl 源表，搜不到自己的挂载点就报警。
  • 备份配置：接收机配置导出一份存好，换设备时能快速恢复。
