从零搭一台自己的 RTK 基准站

不用买测绘主机，也不用开商业 CORS 账号。一台刷了 Armbian 的电视盒子（玩客云、树莓派、香橙派都行）、 一个能进基准站模式的 RTK 模块、一根架在屋顶的室外天线，再加上开源的 2RTK Server，就是一套能常年跑的家用基准站：自动标定自己的坐标， 把 RTCM 差分推给自己的 Caster、推给 RTK2GO，或者干脆只服务局域网里的流动站。

这一页是从装系统到日常运维的完整流程，每一步都配真实界面截图。 本页对应 2RTK Server v3.1.3，实测平台是 Amlogic S905L3B 机顶盒（Armbian， Ubuntu 22.04，aarch64）+ Quectel LG290P 模块（CH340 USB 转串口）。

这个程序到底在做什么

一句话：把一块 GNSS 接收模块，变成一台独立运行的 RTK 基准站。 它从串口读模块吐出的 RTCM 3 差分数据，通过网络分发出去，让野外的流动站拿到厘米级定位。

但它不只是个数据搬运工，还会自己动手：

  • 自动标定基站坐标到厘米级——自己驱动模块走完一整套命令序列，不用你背指令。
  • 失败自动回滚——任何一步出问题，都把模块恢复到标定前的状态，不会把它留在半残模式里。
  • 注入基站元信息，让流动站知道基站在哪、用的是哪个坐标系。
  • 提供 Web 界面，配置、实时监控、固件检查全在浏览器里点。

三种运行模式

模式作用什么场景用
none读模块，只在本地显示，不对外输出台面测试、首次验证
serial从串口读模块，通过 NTRIP 分发出去基站正常运行状态
relay从另一个 Caster 拉流，再重新分发打通网络、扩展覆盖、给已有站做备份

数据往哪里去

三个出口互相独立，勾哪个跑哪个，可以任意组合：

  1. 云端 NTRIP Caster —— 把流推到公网服务器，别处的流动站就能用。
  2. 内置本地 Caster —— 直接在盒子上对局域网提供服务，不依赖公网。
  3. 数传电台 —— 通过第二个串口把差分推给 UHF 电台，野外没网也能用。

顺序里唯一容易违背的一条：别在天线还没上屋顶的时候就去配串口。 配串口会让模块开始出数据，你会看到「有卫星、没固定解」，然后误以为是软件问题。

为什么必须先架天线？因为模块要「看见」卫星才能自己算出高精度的位置。 天线放在窗台上，卫星只收到七八颗、还都在一个方向，模块永远进不了固定解； 等你在网页里点标定卡住的时候，再回屋顶重新架一次，前面的工作全得重做。

标定这件事，有两种完全不同的走法

坐标怎么来，取决于你手头有什么、以及模块能不能自己切换成流动站。 这也是本页最容易写错的地方——很多教程默认「所有模块都能自动标定」，实际并非如此。

走法适合谁具体怎么做
走法 A
原厂软件先设基准站		 手头有模块官方配置工具；单频 / 单基准站模块；不想在屋外开电脑 在室内电脑上把模块接 USB，用模块厂商的配置程序（LG290P 用 Quectel 的工具、u-blox 用 u-center） 直接设成 Base 模式并固定坐标。然后再把模块插进盒子，盒子只负责把 RTCM 搬出去。
走法 B
程序自动标定		 模块支持在 Base / Rover 之间切换（双模）；或是系统预留的型号 模块插好、天线架好，直接在网页的「一键标定」里选CORS 一键固定， 程序自己把模块切成流动站、连 CORS 拿固定解、取平均，再写回基准站坐标。
走法 C

本页的测试机情况，供你对号入座。实测用的是 Quectel LG290P（固件 LG290P03AANR01A03S），它是目前系统里唯一做过真机验证的型号， 走法 B 的自动标定能完整跑通。系统里还预留了 u-blox ZED-F9P、Unicore UM960 / UM980、Quectel LC29H(BS) 等型号档案， 但这些没有在真机上验证过。

非 LG290P 的模块，建议走法 A 或走法 C：先用流动站模式把天线坐标测准，把坐标存进系统； 再用这个坐标把模块设成基准站模式。这样即使自动切换不成功，坐标也是对的。

最容易被误解的一点：算坐标的是模块，盒子只负责搬字节。 RTCM 里的基站坐标（1005 电文）由模块自己广播，盒子既不改也不猜。 所以主机要求低到离谱——1 GHz ARM、512 MB 内存就够，一台十年前闲置的机顶盒完全能胜任。

也正因为如此，把模块设成基准站这件事，可以完全在电脑上先做完， 再插进盒子——盒子根本不参与坐标计算。这就是主线的第 ③ 步。

第一步：把盒子刷成一台 Linux 主机，并装好程序

机顶盒出厂是安卓，我们要的是 Armbian（Debian 系）。这一步是整篇里唯一可能卡住的地方， 因为不同型号盒子差别很大——但只要刷成功了，后面全是点鼠标。

  1. 确认型号，找对镜像

    拆开看主控丝印，或查盒子型号对应的 SoC。拿到 SoC 后去 Armbian 官网的 Download 页找对应板型；玩客云（OneCloud，S805）这类没有官方板型的， 用社区维护的 Armbian 镜像。树莓派最简单——直接装官方 Raspberry Pi OS 64-bit 也行， 2RTK Server 只要求 Debian 系 + Python 3.8 以上。

  2. 烧录到 SD 卡或 U 盘

    用 balenaEtcher 或 Rufus 把 .img 写进去，比命令行 dd 少踩坑。 部分 Amlogic 盒子需要用厂商 USB 烧录工具走线刷，或者先短接进入刷机模式—— 这一步看社区帖子，同型号的教程基本通用。

  3. 首次启动：只插网线，别急着折腾

    网线接到路由器，通电，等两三分钟，在路由器后台找新出现的设备 IP，然后 ssh root@<盒子IP>。Armbian 首次登录会强制改 root 密码并建一个普通用户， 顺手把时区设成 Asia/Shanghai。

  4. 固定 IP，别让它变

    基站要长期跑，IP 一变你所有书签和监控都失效。用 nmtui（或 armbian-config → Network）把有线网卡设成静态地址，或者在路由器里做 DHCP 绑定。 两个都做也不冲突。

  5. 系统收尾：更新、对时、装 Python

    shell · 系统初始化
    # 换源 + 更新（国内盒子建议先换清华或中科大源，armbian-config 里有现成菜单）
sudo apt update && sudo apt full-upgrade -y

# 时间必须准：NTP 同步不上，RTCM 的时间戳就是错的
sudo timedatectl set-ntp true
timedatectl status

# 装 Python 与 venv（安装脚本会自己补，但先装好省得它报错）
sudo apt install -y python3 python3-venv python3-pip

    顺便把没用的桌面、蓝牙、HDMI 输出关掉能省一点电，也少几个出问题的环节。 散热片一定要贴——机顶盒金属壳本来就闷，跑久了降频，串口会开始丢字节。

第二步：在室外把天线固定好

这一步和软件一点关系都没有，但它决定了整套基站能不能成。 盒子那边先跑到「装好程序」就停下来，回来架完天线再继续——顺序反了， 你会在装完、配完、标定卡住的时候才发现天线位置不行，白忙一场。

为什么插在这一步？这四步（架天线 → 测相位中心 → 原厂软件设基准站 → 插回盒子） 彼此咬得很紧：天线位置决定了坐标，坐标要由模块在能看见天空的状态下测出来。 所以它们必须连着做完，中途不要跳去写配置页。

先分清你现在是做临时测试还是永久固定——这两件事的天线装法完全不同。

天线怎么放能拿来干什么
临时测试 四臂螺旋天线 + 磁吸底座 吸在窗外即可 验证链路通不通、能不能收到差分。用几天、随时能拆
永久固定 GNSS 测量蘑菇头天线 + 立杆 楼顶 / 开阔地带的固定立杆上 长期跑基站。坐标定了就不该再动

临时测试把天线放在窗外是可以的，只要它朝向天空的视野够用。 但别把临时配置当成品用：磁吸底座夹在窗框上，风一吹就挪位置，窗玻璃和墙体还会挡掉一大片低仰角卫星， 卫星数上不去、固定解时有时无。要长期跑，请到楼顶或开阔地带固定。

另外，两种天线的相位中心不一样。你在窗外用螺旋天线标定出来的坐标， 换成蘑菇头上屋顶之后必须重新标定一次——天线换了，坐标就作废了。

选位置：三个硬条件

条件要求不满足会怎样
天空视野 朝上的半球基本无遮挡，尤其南向低仰角要开阔（北半球卫星主要在南方） 卫星数上不去、PDOP 变差，永远进不了固定解
刚性固定 膨胀螺栓打进承重墙 / 立柱，或专用立杆 + 三脚架配重压牢 风吹就晃，坐标永远在漂；标定完了等于白标
远离干扰 离开大功率发射天线、金属水箱、太阳能板、微波炉这一类的设备 信号被压制或多路径反射，采集出的坐标有系统偏差

天线一旦固定，就不要再动它。哪怕只是拧松一点转个角度，仰角一变，相位中心的位置就变了， 之前写进模块的坐标全部作废——而模块不会报任何错，只是所有流动站的结果都整体偏了一个固定量。 这是自建基站最常见、也最难发现的错误。

馈线这三件事做好，能省掉后面一半的返工：

  • 接头防水——SMA 接头先缠自粘防水胶带，再套热缩管。室外接头进水是基站掉线的头号原因。
  • 留滴水弯——馈线进屋前向下垂一段 U 形，水顺着最低点滴走，不会倒灌进墙洞。
  • 别打死折——馈线最小弯曲半径按说明书来，硬折一次内部就伤了，损耗会在 SNR 上体现出来。

测天线相位中心：模块要的是这个点

这里有个概念必须先说清：RTCM 里的坐标不是立杆底部、不是螺丝孔、不是楼顶地面， 而是天线的相位中心（Antenna Phase Centre，APC）——一个在天线内部、 跟着卫星信号入射角变化的小区域。

你在测量或者填坐标时，目标点永远是天线的相位中心。 如果手上的已知坐标是从地面控制点量出来的，就要把「天线高」加上去，换算到相位中心。

你手上的坐标怎么换算到相位中心
地面控制点（标石中心）加天线高：从控制点到天线参考点（ARP）的垂直距离，再加天线自身的相位中心偏移
立杆顶端（天线底面）加天线厂家给出的相位中心高度（通常几厘米，写在规格书里）
已经是相位中心（别人用流动站测的）直接用，不用换算

天线高要用垂直高，别用斜高。量斜高再乘余弦，多一步换算就多一个出错机会。 量两次、换人复核一次，几厘米的差错在 RTK 里就是几厘米的系统误差。

第三步：在电脑上用原厂软件，把模块设成基准站

天线架好之后，先别急着把模块插进盒子。拿一台电脑，把模块接上 USB， 用模块厂商自己的配置工具把它设成基准站模式——这一步做完，模块自己就会往外吐 RTCM 3 数据了。

各家工具不一样，但要做的事情是同一件：

模块配置工具设成基准站要做的事
Quectel LG290P Quectel 官方配置工具（PQTM 指令集） 把工作模式设为 Base；填入坐标（已知坐标，或先让它自收敛）；打开 RTCM 3 输出
u-blox ZED-F9P u-center TMODE3 设为 Fixed 或 Survey-in，填坐标；在 RTCM3 里勾选 1005 / MSM4 系列

坐标从哪来？如果这一步你还没有精确坐标，两种做法： 一是让模块先做自收敛（Survey-in）——在屋外架着等十几分钟到一小时，得到分米级坐标，够用但不精确； 二是接一台流动站、或者等盒子装好之后用 CORS 一键标定把坐标测准，再回来改。 建议后一种：先让模块以自收敛坐标跑起来，等整套系统通了，再用标定把坐标换成厘米级的。

必须确认模块真的在输出 RTCM

设完之后别急着拔，先在电脑上看一眼输出。任何一个串口工具都能看：

  • 串口参数：一般是 115200 8N1（以模块规格书为准）。
  • 你会看到一串不全是可读文字的数据——那是 RTCM 二进制报文，正常。
  • 如果主要是 $GNGGA、$GNRMC 这种以 $ 开头的可读行，说明模块还在 NMEA 模式，RTCM 没打开。

这一步验证过，后面省很多事。模块在原厂软件里就已经能吐 RTCM， 插进盒子之后只要串口对上，数据立刻就有；否则你会分不清是模块没配好，还是盒子的串口配错了。

第四步：把模块插进盒子，确认系统认得它

模块已经在电脑上配成基准站了，现在把它插进 Armbian 盒子。接线就这么几根：

接线示意（模块已配好，盒子里不再修改模块）

第八步：坐标标定（最关键的一步）

基站只有非常精确地知道自己的位置，才能产出有用的差分数据。 基站坐标差一米，每个流动站的输出就差一米，而且事后没有任何软件能救回来。

先分清两件事。「把模块设成基准站」是模式问题——模块是 Base 还是 Rover； 「标定」是坐标问题——基准站对外宣称自己站在哪个点上。 走法 A 在电脑上已经把模式设好了，但坐标可能只是个粗测值，这一步就是要把坐标弄准。 走法 B 则是一次把模式和坐标都办掉。

先确认你要走哪条路

回到前文的三种走法，这里给一个更直接的判断方式：

方式一（走法 B）：CORS 一键固定

最准、也最自动。程序会把模块临时切成流动站，连上 CORS 挂载点拿固定解，稳住之后取平均， 再把平均坐标写回模块并切回基准站模式。整个过程不需要你动手。

端口和坐标系是配对的。常见的国内 CORS 服务商会在多个端口上提供同一批挂载点， 一个基准对应一个端口：8002 → WGS84，8001 → CGCS2000。

挑挂载点时看两点：

  • 覆盖你的区域——挂载点名字一般带地区或网络标识。
  • 播发多星座多频——名字里带 RTCM33、5G16F（五星十六频）之类的就是这个意思。

点开始之前：天线必须固定牢靠，整个标定期间不能动。 标定页自带的那段说明写得很清楚——测的是天线相位中心，而且天线一旦开始移动，测出来的就是废数。 程序会丢弃跳变超过 500 米的样本，但天线本身在晃时，固定解压根出不来。

方式二（走法 B 的变体）：仅测量

针对一种特定情形：你想测定基站坐标，但基站模块本身当不了流动站；或者你手头已经有一台在基站位置拿到固定解的流动站。 和 CORS 一键固定的区别是：

  • 基站模块不会被切成流动站模式。
  • 差分数据不会灌进基站模块。
  • 位置由另一台流动站提供——手机、手簿，或者另一台接收机。

对于只能当基准站的模块，这是唯一能自动测出坐标的方式，测完再回去用走法 C 把坐标写进模块。

方式三（走法 C）：手动写入坐标

这个点位以前测过——控制点、老基站、上次标定过的同一个天线位置——就直接填。 走法 A 里用原厂软件设基准站时填的坐标，也在这里补录一份，好让程序记住。

输入格式
纬度十进制度，例如 25.203523

椭球高米，例如 138.316

务必确认坐标系和你的流动站一致——常用 WGS84，国内某些场景用 CGCS2000。弄错了，每个流动站的输出都会带一个固定偏移。

「天线没挪过」是这条路的前提。已知坐标之所以能直接用，是因为天线相位中心还在原来那个点上。 天线拆过、挪过、立杆换过位置，这个坐标就作废了——继续用会让所有流动站一起偏。拿不准就去测一次。

只能当基准站的模块（单基准站模块）只能走这条路，或者退一步用自收敛。 它不是「不会用自动标定」，而是物理上切不成流动站，程序也没法替它测坐标。

方式四（兜底）：自收敛 Survey-in

不依赖外部条件的选项——不用 CORS 账号，不用网络。模块对自己的单点位置做长时间平均。

参数含义常见取值
观测次数平均多少个定位结果2000～5000

自收敛不等于已知点。它受限于模块的单点精度，一般只有 1～2 米，不是 CORS 标定的替代品。 拿来做相对基准够用，拿来当控制点会出事。要做绝对坐标，老老实实走 PPP 或 CORS。

程序会持续监控收敛情况，只在位置稳定时才收尾——滚动 3σ 离散度低于 2 厘米并保持 60 秒。

启动之后：它会自己跑完

方式选好、参数填完，点「开始」，确认对话框会再强调一次天线不能动。之后程序按固定阶段往下走， 你只需要看阶段指示器。

程序内部按这九步走，卡在哪一步就能直接定位问题：

  1. 让数据面让出串口。一边推流一边标定是做不到的。
  2. 识别模块——发版本查询、读回应答。
  3. 备份当前配置，出问题好回滚。
  4. 把模块切到流动站模式，配置所需的 NMEA 输出。
  5. 连上 CORS 挂载点，把差分数据灌进模块串口。
  6. 等固定解。这要求良好的天空视野：质量位必须连续 30 秒达到 4。
  7. 采集样本——按设定时长（默认 300 秒），3σ 剔除异常值后对剩下的取平均。
  8. 把平均后的坐标写进模块，作为固定基站坐标。
  9. 把模块恢复成基站模式，回放报文配置，重启并核验。

FIX_WAIT 是最需要耐心的阶段。面板里两个数字告诉你顺不顺：

  • 质量（Quality）——必须爬到 4。停在 1 或 2，说明差分没送进模块，或者天空视野太差。
  • 已固定（Fixed for）——必须连续到 30 秒。如果一直清零，说明固定解在反复掉，有东西不稳定。

「固定解」到底是什么意思

模块在 GGA 语句里报一个质量位：

质量位含义能当基站用吗
1单点解不能
2差分 / 浮动解不能
4RTK 固定解能
5RTK 浮动解不能

程序要求质量位连续 30 秒为 4，同时卫星数至少 12 颗、PDOP ≤ 2.0。 180 秒内没达成，会尝试降级用浮动解——但前提是浮动解足够稳。两者都不行，标定判失败，模块按备份回滚。

标定到底往模块里写了什么

标定成功后，模块里保存的是：

  • 平均后的 ECEF 坐标——经过 3σ 剔除后被采纳样本的算术平均（不是模块内部卡尔曼滤波的输出）。
  • RTCM 报文配置——播哪些报文类型、什么频率。
  • 基站模式——模块留在基站状态，不会停在流动站。

程序还会在数据库里记一条标定历史：用的哪种方式、采了多少样本、最终离散度、得到的坐标。状态页显示的基站位置就来自这里。

天线相位中心（APC）：RTCM 里的坐标指的是天线相位中心，不是立杆底部、也不是天线外壳上的螺丝孔。 你的天线如果要重复拆装，做完标定后把立杆位置做上记号，下次装回同一个位置；否则重新标定。 这一条比选哪种标定方式重要得多。

标定失败了怎么排查

程序失败时话很多——它会告诉你哪一项检查没过、观测到了什么。下面按症状分。

识别阶段报「模块无应答」

串口被别人攥着了，通常是主程序的数据线程还在收上一轮的尾。

  • 等 20 秒再重试。
  • 还是不行，就先停服务、标定、再启服务。

「等待固定解超时」——质量位卡在 1 或 2

最常见的标定失败。按顺序查这四项：

  1. CORS 账号权限。有些账号只给伪距（DGPS）差分，或者只授权某个坐标系。你能连上、能收到数据，但模块就是不采用这些差分。跟服务商确认。
  2. 挂载点是否对口。距离太远的网络、或精度等级不同的挂载点可能没用。优先选标明基站级、且覆盖你所在区域的。
  3. 端口与坐标系配对。8002 是 WGS84，8001 是 CGCS2000。对不上就是这个症状。
  4. 天线遮挡。质量位在 4～5 附近徘徊却始终锁不住，就是这个原因。把天线挪到天顶开阔处。

「有 GLONASS 观测但没有 MT1230」

这是警告，不是失败：

该挂载点播发了 GLONASS 观测（1084）却没有播 MT1230 码相位偏差。模块虽然能跟踪 GLONASS，但通常无法把它们纳入模糊度固定，会明显降低固定成功率。

触发这条警告的体检行长这样：

日志
[CORS_DOWNLINK] 976 B/s，MSM4=GPS+GLONASS+Galileo+QZSS+BDS，1005=30帧，1230=缺失

五个星座、接近 1 KB/s、基站位置也在——唯独 1230 缺失。这一行里没有任何一项像故障， 所以它值得被打印出来：链路是健康的，字节数一直在涨，卫星数甚至还在变好。 没有这道体检，你根本不会发现这条流是不完整的。

但「不完整」不等于「不能用」。同一块模块、同一个账号、同一根天线、同一天，唯一变量是挂载点：

挂载点MT1230结果样本数原始标准差（E/N/U）verify_delta
RTCM33_GRCEJ无DONE605.4 / 7.9 / 1.2 cm0.0001 m
RTCM33_GRCEJ_CPB有DONE8119.8 / 75.8 / 6.0 cm0.0000 m

两次都固定成功了。不带 1230 的那个挂载点反而给出了更紧、更一致的解： 整体精度 9.6 cm，而带 1230 的那个是 78.6 cm。所以 1230 确实是差分流一个真实且值得追求的属性， 但它并不是决定你能不能固定的那件事。

那一周真正决定结果的，完全在挂载点的上游：

已用时质量位卫星PDOP阶段提示备注
0 s11199.99等待 0/300 秒模块刚上电
60 s1134.44等待 29/300 秒
180 s1143.58等待 117/300 秒
250 s2181.96等待 242/300 秒
370 s2202.7超时浮动解命中率 0/560

那一次里质量位从 1 爬到了 2，说明差分确实被采用了——链路没问题。 但质量位始终没到 4。把模块显式重启一次，天线原地不动、挂载点也用同一个，再跑一遍， 一分钟内质量位就到 4，正常完成。

四点值得记住：

  1. 1230 是质量信号，不是准入门。有得选就优先选播发它的挂载点；没得选也照常标定。别为了找一个带 1230 的挂载点耗掉几个小时。
  2. 先重启模块，再去怀疑 CORS 账号。长时间上电的模块会攒下过期的星历、漂掉的钟模型、或者卡住的跟踪通道，质量位会稳稳停在 2，不管差分有多好。断电重上电，等它完整重新捕获一遍再试。这一个习惯能解决绝大多数「CORS 坏了」的报告。
  3. 失败诊断列的是原因清单，不是优先级排序。程序会指向账号权限、挂载点匹配度、模块状态——但真正的原因也可能一个都不在里头。
  4. 卫星多不能当证据。20 颗卫星、PDOP 1.96、质量位却卡在 2，那是接收机跟踪的问题，不是视野的问题。

「浮动解不稳定」

程序尝试降级用浮动解，但拿不到稳的——349 个候选历元里只有 7 个满足准入。原因同上：坐标系不匹配、账号权限、或者天线遮挡。

「手动写入被拒」

手动坐标必须和标定记录里存档的坐标一致，否则程序拒绝写入。检查一下是不是抄错了小数点，或者把纬度经度写反了——这是最常见的两件事。

第九步：把 RTCM 推到云端 NTRIP Caster

基站标定完、模式进了 serial，它才刚刚开始产出 RTCM 数据。这些数据现在只在本机里打转，得有一个出口把它送出去，流动站才收得到。

2RTK Server 设计上给了三个互相独立的出口，可以只开一个，也可以同时开：

① 上游 NTRIP Caster

把你的基站作为一个「源」，推到公网上的 Caster（自建的、RTK2GO、或者别的公共服务）。这是最常见、也最通用的做法——流动站只要能连 Caster，就能用你的基站。

② 内置本地 Caster

程序自己就是一台 Caster，监听 2102 端口。适合局域网内用，或者你不想依赖任何外部服务的时候。挂载点固定叫 2RTK。

③ 数传电台

通过 USB 接一台透传电台，把 RTCM 打到空中。适合完全没网的野外，或者测绘队习惯用电台的场合。

这一节讲 ①，② 和 ③ 在后面两节。

出口 ① 要填什么

进 Settings 页面，往下滚到 NTRIP Caster Upload 区域。要填的东西不多，一共五项：

Caster 地址你那一台 Caster 的域名或 IP。自建的填自己服务器的地址；用 RTK2GO 就填它给的地址。
端口一般是 2101。少数服务会另指端口，按对方给的填。
挂载点你的基站在 Caster 上的名字，流动站在列表里就是靠这个名字找基站。
用户名 / 密码Caster 那边给你开的源账号，不是流动站账号。两者权限不同，别搞混。
上传间隔多少秒推一次。默认值就够用，除非 Caster 那边有明确要求。

填完点保存，一定要回到开关那里确认它是打开的。这一步漏掉的人很多——参数全对，但开关还停在关闭状态，然后开始怀疑人生。

保存后回 Status 页面，出口 ① 的状态应该从「未连接」变成已连接，并且能看到已经推送出去的字节数在涨。只要这个数字在动，你的基站就已经在线了。

自己搭 Caster 的好处是数据可控。想给谁开账号就给谁开，想收就收，挂载点名字自己定，还能同时管好几台基站。搭建过程单独写了一页 → NTRIP Caster 搭建。装好之后，把出口 ① 填成你那台服务器的地址、端口 2101、挂载点和密码即可。

用 RTK2GO 的公共服务：申请挂载点

RTK2GO 是免费的公共 Caster，很多人拿它起步。它不需要注册账号，也不需要密码——只要在线申请一个挂载点名字，然后直接往上推就行。但它的挂载点命名有硬性规则，第一次用很容易被拒。

  1. 想一个符合规则的名字。4～20 个字符，只能用字母、数字、连字符和下划线。下面会细讲规则。
  2. 把用户名和挂载点都填成这个名字，密码留空或随便填一个非空值（有些客户端不允许空密码）。
  3. 第一次连接时它会自动建点。只要名字没被占用、格式合规，连接成功的同时挂载点就在 RTK2GO 上出现了。
  4. 去它的挂载点列表里确认一下。刷新列表能看到自己的名字，就说明推上去了。一般几十秒内出现。

挂载点命名规则

规则说明反例
长度 4～20 字符太短会被拒，太长也会AB、myveryverylongbasename
只用 [A-Za-z0-9-_]字母、数字、连字符、下划线my base（空格）、基站点（中文）
不能以大写 A 开头RTK2GO 保留 A 前缀给内部用ABCbase
不能叫 Base和保留字冲突Base、BASE
全球唯一重名会被拒绝，换一个再试别人已经用了的常见地名
48 小时内会收到邮件若被判定不合规，会邮件通知并删除该点——

一个好用的命名套路：地区缩写 + 用途 + 序号，比如 SZRTK01、HZ-Base1、CD_RTK_A。既唯一又一眼能看出是哪儿。

公共 Caster 是「尽力而为」的服务。别把生产依赖挂在上头：它会限速、会清理长期无数据的点、也会因为滥用而临时关服务。真要用，就自己搭一台——那才是完全可控的。

第十步（可选）：中继模式，把别人的基站搬过来

如果你手边没有很好的架站位置，但附近已经有一个信号不错的 Caster 挂载点，那你可以不架基站，只用 2RTK Server 做一台「中继」——从上游拉流，再转给自己的流动站或者另一个 Caster。

relay 模式不读串口，也不做任何标定。它做的事只有一件：连上指定的上游挂载点，把 RTCM 原样接下来，然后走你配置的出口分发出去。相当于给你的 RTK 数据流加了一站。

什么时候该用中继

补盲区

主基站覆盖不到的山谷、工地低洼处，在中间放一台中继（接一台 4G 路由），把信号接力进去。

做统一入口

手上有好几台上游基站，想给队里一个固定的入口，不用每次改流动站配置。

数据落一份

上游是公共 Caster，你想自己留一份，同时保证本地访问不受它限速影响。

切成 relay 模式

进 Settings，最上方的运行模式一栏，把 serial 改成 relay，保存。

切换模式会停掉当前的 RTCM 输出。如果你的基站正在给现场供数据，先通知一声再切。切回 serial 之后不需要重新标定，坐标存在标定记录里，但模块需要重新捕获一遍。

拉取上游挂载点列表

填好上游 Caster 的地址和端口，点「获取挂载点列表」。程序会连上去把 sourcetable 拉下来，解析成一个可选的下拉列表——比手抄挂载点名字靠谱得多。

如果列表是空的，多半是这三个原因：地址或端口错了、上游 Caster 不允许匿名获取 sourcetable、或者本机出网被防火墙拦了。先用 curl 在终端里试一下最直接：

终端# 拉 sourcetable 验证连通性
curl -s --max-time 10 http://你的Caster地址:2101/ | head -20

能打出一堆 STR; 开头的行就是通的。打不出来说明是网络层的问题，跟 2RTK Server 无关。

选中挂载点并填源账号

从上一步的列表里选中你要转的那个，然后把上游 Caster 给你的源账号填进去。注意是中继在扮演「流动站」去拉流，所以要的是能读这个挂载点的账号——很多 Caster 允许匿名读，那就不用填。

确认数据在流动

保存后回 Status。中继模式的状态页会显示上游连接状态、收到的字节数、以及往每个出口转发的字节数。数字在涨就是通了。

中继会把上游的基站坐标一起转出去。也就是说流动站拿到的基站点位是上游那台的，不是你中继所在的点位——这是中继的正确行为，但也意味着中继本身的物理位置和精度无关，你放哪儿都行，只要网络通。

不要把别人的基站拿去公开转播。公共 Caster 上的数据不等于可以随便再分发，尤其是标了机构名的挂载点。自己队内用没问题，对外转播前先确认授权。

第十一步（可选）：打开内置本地 Caster

不想依赖任何外部服务？2RTK Server 自己就是一台 NTRIP Caster。打开之后，局域网里的流动站直连你的盒子就能拿到差分数据，全程不出内网。

这台内置 Caster 的参数是固定的，不用配置：

监听地址0.0.0.0:2102（所有网卡，端口 2102）
挂载点2RTK（固定，不能改）
账号 / 密码2RTK / 2RTK
最大客户端16 个并发
数据来源当前模式产出的 RTCM（serial 或 relay）

打开开关

进 Settings，找到 Local Caster 那一块，把开关打开并保存。程序会立刻在 2102 端口起一个 NTRIP 服务。

要在防火墙上放行 2102。跟你放行 5757 一样，在盒子上（ufw allow 2102/tcp）和云厂商安全组里都要开。只开一头的结果是「本机能连、外面连不上」。

看客户端连了几台

状态页会列出当前连进来的客户端——IP、连上的时间、已经收到的字节数。用来判断「到底有没有人连上我」很直观。

流动站怎么填

以常见的手簿 / 手机 App 为例，NTRIP 配置里填：

流动站 NTRIP 配置# 内置本地 Caster
地址     192.168.x.x     # 盒子的局域网 IP，或 2rtk.local
端口     2102
挂载点   2RTK
用户名   2RTK
密码     2RTK

盒子的 IP 在状态页顶部就能看到，也可以在路由器里给它绑定一个固定 IP。用 2rtk.local 更省事，但有些安卓手簿不认 mDNS，这种时候还是填 IP 稳妥。

内置 Caster 和上游 Caster 上传不冲突，可以同时开。一台盒子既给公网供数据，又给身边的流动站直连，是最常见的部署形态。

第十二步（可选）：接数传电台

完全没网的地方，或者队里本来就用电台，那就把 RTCM 打到空中。2RTK Server 支持通过 USB 接一台透传电台，把 RTCM 流原样送出去。

「透传」是关键：电台不解析 RTCM，只把它当成一串字节发给对端。所以电台本身不需要懂 RTK，只要带宽够、延迟小。9600 波特的老电台也能跑——只是 RTCM 报文要精简一些。

接线与识别

USB 电台插上盒子，跟接 RTK 模块一样，先在 Settings 的串口扫描里看看系统认不认。电台一般会显示成 /dev/ttyUSB1 这样的设备，和 RTK 模块的 ttyUSB0 分开。

配置电台出口

在 Settings 的出口 ③ 区域填电台的串口、波特率，然后打开开关。

现象原因与处理
串口打不开电台被别的进程占用，或者权限不对。检查是不是还有一个旧的 2RTK 进程在跑。
电台收到数据但流动站不固定波特率不匹配，或者空中速率设得太低导致丢包。两边都调成 9600/8N1 先试试。
能固定但很慢才收敛带宽不够。把 RTCM 报文类型减到只留必要的 1005 + MSM4，别全开。

电台方案的可靠性和距离强相关。视距、天线高度、功率、周围遮挡，任何一个变化都能让结果差很多。真要长期用，做一次链路余量测试比反复试参数有用。

流动站怎么连：三种场景

基站这边搭好了，最后一步是把流动站接上去。填的东西不多，但「地址填什么」取决于你在哪种网络环境里，这里把三种常见场景摊开说。

场景地址端口说明
同一局域网 盒子 IP 或 2rtk.local 2102 连内置本地 Caster，挂载点 2RTK。最快、最稳，不依赖外网。
公网 / 异地 你自建 Caster 的域名或 IP 2101 连上游 Caster 上的挂载点。需要流动站有移动网络，基站也要能出网。
无网现场 —— —— 走电台。流动站的电台和基站电台同频同速率，串口那边把 NTRIP 关掉、改成直接读串口。

连上之后确认这三件事

  1. 看质量位变成 4。流动站解算状态里那个「RTK 固定 / Fixed」出来了，才算真的吃到了差分。只有 2 或者 5 说明数据在流但精度不够。
  2. 看基线长度。流动站离基站越远，固定的可靠性越差。城市里建议控制在 10 km 以内，开阔地可以放到 30 km 左右，再远就要靠多基站网络了。
  3. 看卫星数是否接近基站。如果基站 30 颗、流动站只有 12 颗，说明两边看到的天空不一样，公共卫星集不够，固定会很脆弱。

坐标系一定要成对。基站标定用的坐标系，和流动站解算用的坐标系必须是同一个。用 8002 端口出来的是 WGS84，用 8001 出来的是 CGCS2000——选错也能连上，但永远固定不了，或者固定了坐标是偏的。

日常维护：它得能自己活很久

基站装好只是开始。这东西要挂在楼顶、插着电、连着网，连续跑几个月甚至几年。能不能自己活下来，比装得多漂亮更重要。

常用命令

程序以 systemd 服务的形式运行，服务名 2rtkserver，安装目录 /opt/2RTKserver/。日常就这几条：

终端# 服务管理
sudo 2rtkserver status          # 看是否在跑、跑多久了
sudo 2rtkserver restart         # 重启，改完配置后用
sudo 2rtkserver stop            # 停止
journalctl -u 2rtkserver -f     # 实时看日志，Ctrl+C 退出
journalctl -u 2rtkserver -n 200 # 只看最近 200 行

盒子重启后服务会自动起来，这是 systemd 装的时候就配好的，不用手动干预。如果发现重启后没起来，用 systemctl is-enabled 2rtkserver 查一下是不是被禁用了。

升级要用界面里的 Updates

登录 Web 界面，点 Updates，它会把新版本拉下来、备份旧版本、重启服务。整个流程是原子的，失败了会回滚。

不要用 install.sh 去「升级」。那个脚本是做全新安装的，它会重建目录结构。在已经跑着数据的机器上重跑，可能把 calibration.db 覆盖掉——你的标定就没了，得重新跑一遍。

备份这台机器

真正值钱的东西只有一个文件：标定记录。

终端# 备份标定记录
sudo cp /opt/2RTKserver/calibration.db ~/calibration-$(date +%F).db

把它拷到自己电脑上，或者丢进网盘。换盒子、重装系统的时候把它放回原位，就不用重新爬上天台等 70 秒收敛了——虽然那 70 秒也不长，但要重新爬一趟梯子，感觉就完全不一样。

让它长期稳定跑下去

  1. 时间要准。确保 NTP 是正常的（timedatectl 看 System clock synchronized: yes）。时间跳变会让 RTCM 时间戳错乱，流动站直接不认。
  2. 防雷接地。室外天线是整栋楼最高的金属物之一。馈线进户前加避雷器并可靠接地，这不是可选项——雷雨天烧掉的不只是模块。
  3. 供电要稳。别用劣质 USB 电源。电压跌落会让盒子反复重启，症状看起来像「程序老是挂」。
  4. 散热。机顶盒刷 Armbian 常年跑满，夏天烫手很正常，但贴着墙放在密闭箱里就会降频甚至死机。留点空隙。
  5. 加个监控。最简单的做法：用另一台机器每分钟拉一次状态页，非 200 就发消息。或者直接看上游 Caster 上你的挂载点还在不在。

远程访问的安全底线

默认账号是 admin/admin。装完第一件事就是改密码——Password 页面。如果 5757 端口暴露在公网，一个默认密码的盒子基本上等于公物。

更稳妥的做法是不要把 5757 直接开到公网：用 WireGuard / Tailscale 组一个内网，或者只允许固定 IP 访问，需要的时候再开。2101 / 2102 这些数据端口反而不太敏感，它们只吐 RTCM。
