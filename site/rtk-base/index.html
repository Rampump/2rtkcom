在家搭站

一台旧盒子 + 一个 RTK 模块，搭自己的基准站

不用买测绘主机，也不用开商业 CORS 账号。一台刷了 Armbian 的电视盒子（玩客云、树莓派、香橙派都行）、 一个能进基准站模式的 RTK 模块、一根架在屋顶的室外天线，再加上开源的 2RTK NTRIP Server，就是一套能常年跑的家用基准站：把 RTCM 差分推给自己的 Caster， 或者推到 RTK2GO 这类公共 Caster，十几公里内的流动站都能用上你的固定解。

Armbian / Debian 512 MB 内存够用 2RTK NTRIP Server RTCM 3.x

这里最容易被误解的一点是：算坐标的是模块，盒子只负责搬字节。 RTCM 里的基站坐标（1005/1006 电文）由模块自己广播，盒子既不改也不猜。 所以对主机的要求低到离谱——1 GHz ARM、512 MB 内存就够，一台十年前闲置的机顶盒完全能胜任。 2RTK NTRIP Server 的官方测试平台就是 Armbian 机顶盒和玩客云。

第一步：把盒子刷成一台 Linux 主机

机顶盒出厂是安卓，我们要的是 Armbian（Debian 系）。这一步是整篇里唯一可能卡住的地方， 因为不同型号的盒子差别很大——但只要刷成功了，后面全是点鼠标。

  1. 确认型号，找对镜像

    拆开看主控丝印，或查盒子型号对应的 SoC。拿到 SoC 后去 Armbian 官网的 Download 页找对应板型；玩客云（OneCloud，S805）这类没有官方板型的， 用社区维护的 Armbian 镜像。树莓派最简单——直接装官方的 Raspberry Pi OS 64-bit 也行， 2RTK Server 只要求 Debian 系 + Python 3.8 以上。

  2. 烧录到 SD 卡或 U 盘

    用 balenaEtcher 或 Rufus 把 .img 写进去，比命令行 dd 少踩坑。 部分 Amlogic 盒子需要用厂商的 USB 烧录工具走线刷，或者先短接进入刷机模式—— 这一步看社区帖子，同一型号的教程基本都通用。

  3. 首次启动：只插网线，别急着折腾

    网线接到路由器，通电，等两三分钟，在路由器后台找新出现的设备 IP，然后 ssh root@<盒子IP>。Armbian 首次登录会强制改 root 密码并建一个普通用户， 顺手把时区设成 Asia/Shanghai。

  4. 固定 IP，别让它变

    基站是要长期跑的，IP 一变你所有书签和监控都失效。用 nmtui（或 armbian-config → Network）把有线网卡设成静态地址，或者在路由器里做 DHCP 绑定。 两个都做也不冲突。

  5. 系统收尾：更新、对时、装 Python

    shell · 系统初始化
    # 换源 + 更新（国内盒子建议先换清华或中科大源，armbian-config 里有现成菜单）
sudo apt update && sudo apt full-upgrade -y

# 时间必须准：NTP 同步不上，RTCM 的时间戳就是错的
sudo timedatectl set-ntp true
timedatectl status

# 装 Python 与 venv（安装脚本会自己补，但先装好省得它报错）
sudo apt install -y python3 python3-venv python3-pip

    顺便把没用的桌面、蓝牙、HDMI 输出关掉能省一点电，也少几个出问题的环节。 散热片一定要贴——机顶盒金属壳本来就闷，跑久了降频，串口会开始丢字节。

第二步：装 2RTK NTRIP Server

这是我自己写的一个开源项目（GPLv3），专门做「把串口 RTCM 变成 NTRIP 流」这一件事： 读模块、标定坐标、往三个出口分发，全在浏览器里配。 源码在 gitcode.com/rampump/NTRIPserver， 国内访问比 GitHub 稳，脚本里也做了 GitHub 回退。

装的时候只需要一行，直接在盒子的终端里粘贴：

shell · 一键安装（GitCode 优先，失败回退 GitHub）
sudo apt-get install -y git && sudo rm -rf /tmp/2rtk-install && (sudo git clone --depth 1 https://gitcode.com/rampump/NTRIPserver.git /tmp/2rtk-install || (sudo rm -rf /tmp/2rtk-install && sudo git clone --depth 1 https://github.com/Rampump/2RTKserver.git /tmp/2rtk-install)) && sudo bash /tmp/2rtk-install/install.sh

从 Windows 浏览器复制时不要手抄。这一行是纯 ASCII、没有换行，粘过去就能跑； 但记事本补的 CR LF、中文全角标点、终端自动折行插进去的空格，都会让它当场失败。

安装脚本会建虚拟环境、装依赖、注册 systemd 服务，装完就能访问：

http://<盒子IP>:5757

http://2rtk.local:5757，重名时自动退成 2rtk-2.local

admin / admin —— 登录后立刻改

安卓手机不解析 .local，用 IP 访问；浏览器打开 2rtk.local 报 502 但 IP 能开，是本机代理（Clash、v2rayN、公司 VPN）劫走了 .local，把 *.local 加进直连列表即可。

第三步：把 RTK 模块接上

模块通过 USB 转串口接到盒子上。插上之后先确认系统认到了设备，再谈别的：

shell · 确认串口设备
# 看插入记录，找 ch341 / cp210x / ftdi_sio 之类的驱动名
dmesg | tail -20

# 两种常见命名：USB 转串口是 ttyUSB0，原生 USB CDC 是 ttyACM0
ls -l /dev/serial/by-id/
ls /dev/ttyUSB* /dev/ttyACM*

然后在 2RTK Server 的 运行设置（/config） 里把数据源选成 serial： 串口留空就会自动扫描，波特率留空则由程序从模块回读， 不用你翻手册猜是 115200 还是 460800。这是这个项目我最满意的一个小设计——换模块不用改配置。

模块本身必须先进入基准站模式

这一步软件替不了你。用厂家的上位机（u-center、QGNSS、Unicore 的工具）把模块设成 Base / 基准站模式，并打开 RTCM3 输出：至少要有 1005（或 1006）加四系统的 MSM 观测电文 （1074/1084/1094/1124，或 1077/1087/1097/1127）。 设完保存成模块的默认配置，掉电重启也不丢。

电文作用建议间隔
1005 / 1006基站坐标（1006 带天线高）10 s
1074 / 1084 / 1094 / 1124GPS / GLO / GAL / BDS 的 MSM4 观测1 s
1230GLONASS 码相位偏差，用 GLO 就得有1 s
1033接收机与天线型号描述30 s

没有模块也能跑：中继模式

数据源选 relay 就能从别的 Caster 拉一路流再转发，适合两种情况： 一是先不买模块，拿别人的公开流把 Caster、防火墙、流动站这几段链路打通； 二是给已有基站做备份——主站挂了，中继这路顶上去。 填对方地址、端口、挂载点，必要时填账号密码，页面上还能一键拉取对方的源表来选挂载点。

第四步：标定天线坐标（最关键的一步）

基准站坐标的误差会原样传给你所有的流动站。基站偏 30 cm，你用这套系统测的每一根桩都偏 30 cm， 而且事后没有任何软件能救回来。所以这一步值得多花半天。

2RTK Server 把标定做进了浏览器（/calibrate）：选方式、填参数、点开始， 程序会独占串口去驱动模块，最后把坐标写进模块，再从空口读回 1005/1006 逐项比对—— 写进去的和发出去的不一致，就直接判失败，不给你一个「看起来成功」的假象。

方式需要准备能到的精度适合谁
CORS / VRS 一个可用的 CORS 账号（地址、端口、挂载点、账号密码） 厘米级（固定解） 附近有 CORS 网、想一次到位
Survey-in 自测绘 什么都不用，但头顶必须开阔 亚米级 / 分米级 只做相对测量、自家院子用
手动输入 已有静态测量 / PPP 解算结果（经纬度 + 椭球高） 取决于你给的坐标 做过控制点、要绝对精度

  1. 读取模块信息

    点页面上的「读取模块信息」，程序会扫波特率、识别型号。内置档案覆盖 u-blox ZED-F9P、Quectel LG290P、LC29H(BS)、UniCore N4 这些常见模块， 能全自动写坐标；UM980 / UM982 / Septentrio 这类没有档案的，仍然能当数据源用， 只是坐标得先用厂家工具写好，程序会从 1005/1006 里读出来显示。

  2. 选方式，等它跑完

    标定期间数据面会被暂时挂起（串口被独占），页面实时显示当前阶段、已用时间、卫星数和解算状态。 天空被挡的时候它不会假装成功，而是老实给一个 sub_meter 或 decimeter 的等级。 中途断电也不会把程序卡死——标定租约 30 秒没心跳就自动放行。

  3. 看清天线相位中心（APC）

    RTCM 里的坐标指的是天线相位中心，不是立杆底部、也不是天线外壳上的螺丝孔。 如果你的天线要重复拆装，做完标定后把立杆位置做上记号，下次装回同一个位置； 否则重新标定。这一条比选哪种标定方式重要得多。

  4. 记下来，存一份

    结果会存进 calibration.db，历史列表里可以复用同一根天线的旧坐标。 自己也抄一份保存好——换盒子、重装系统时，这串数字比任何配置文件都值钱。

Survey-in 不等于已知点。它只是让模块长时间平均自己的单点解，本质仍是米级精度往上收敛一点， 拿来当相对基准够用，拿来当控制点会出事。要做绝对坐标，老老实实走 PPP 或 CORS。

第五步：差分送去哪（三个出口）

2RTK Server 最实用的地方是三个出口完全独立：勾哪个跑哪个，一个出口掉线不会拖死另外两个。 它们共用同一路串口数据，不需要装两套软件。

出口填什么典型用途
① 上传到上游 Caster 地址、端口（一般 2101）、挂载点、密码 推给自己搭的 Caster，或 RTK2GO 这类公共 Caster
② 本地 Caster 监听地址 0.0.0.0、端口 2102，挂载点固定 2RTK，账号 2RTK / 2RTK 手簿、无人机地面站和盒子在同一个 Wi-Fi，直连不绕外网
③ USB 数传电台 电台串口、波特率（要 ≥ 电台空口速率） 野外没网，靠 433 / 410 MHz 电台给流动站发差分

为什么端口是 2101 和 2102 两个

很多人第一次看会以为冲突，其实不会： 2101 是对方 Caster 的端口，你只是往外连，不占本机任何端口； 2102 才是本机真正 bind() 的端口。所以两个同时开完全没问题。

端口属于谁占本机？
5757本程序的 Web 界面占
2101上游 Caster（出站目标）不占
2102本地 Caster占

推到自己的 Caster

自己搭 Caster 的好处是数据可控：想给谁开账号就给谁开，想收就收，挂载点名字自己定， 还能同时管好几台基站。搭建过程单独写了一页 → NTRIP Caster 搭建。 装好之后，把出口 ① 填成你那台服务器的地址、端口 2101、挂载点和密码即可。

推给公开 Caster：RTK2GO

不想维护服务器也不想花钱，就推 RTK2GO。它是免费社区 Caster，全球的流动站都能拉你的流， 代价是数据完全公开——谁都能用，包括你不想给的人。

  1. 申请一个挂载点

    打开 RTK2go 的 New Base Station Reservation 表单，填姓名、邮箱、挂载点名。格式选 Auto Parse，协议留 NTRIP Rev1 就行（95% 以上的连接都是 Rev1）。

  2. 两天内回一封邮件

    提交后会收到一封确认邮件，48 小时内必须回复一次，不回复等于没注册。 之后会再来一封邮件，里面有分配给你的挂载点密码（密码自己填了就用你填的，别填 1234 这种）。 整个流程通常 8 小时内，周末慢一些。

  3. 在 2RTK Server 里填四行

    出口 ①
    勾上「上传到上游 Caster」
    地址 / 端口
    rtk2go.com / 2101
    挂载点
    你申请到的名字，大小写敏感
    密码
    邮件里给的那个

  4. 看它有没有真的上去

    一两分钟后打开 SNIP 的监控页 或 http://rtk2go.com:2101/SNIP::STATUS，搜你的挂载点名。 出现在列表里，说明 RTK2GO 已经收到你的流了。

推公开 Caster 前先想清楚三件事： ① 数据是公开的，你的天线位置等于公开了； ② 坐标不准的基站会污染别人的测量，宁可不推也别推一个 Survey-in 出来的米级坐标； ③ 流量异常、参数错误会被封 IP，先在本机确认电文正常再往外推。

长期运维：让它自己活着

  • 开机自启：安装脚本已经注册了 systemd 服务，断电恢复后自己会起来。用 sudo 2rtkserver status 确认。
  • 看日志：journalctl -u 2rtkserver -f 跟 systemd 日志，或 tail -f /opt/2RTKserver/server.log（1 MB × 3 轮转）。
  • 升级：网页 /upgrade 点一下就行，拉代码、自检、换文件、失败自动回滚。 不要用 install.sh 升级——它结尾的 systemctl start 对已在跑的服务是空操作，文件换了旧代码还在内存里。
  • 备份：calibration.db 存的是你测出来的坐标，等于这套站的资产，定期拷走。
  • 时间：timedatectl 确认 NTP 同步正常。盒子时间飘几分钟，RTCM 时间戳跟着错。
  • 供电与散热：盒子 + 模块用一个质量好的 5 V 电源；夏天加个小风扇或散热片，降频会表现为「莫名丢星」。
  • 防雷：馈线进室前加同轴避雷器并接地。这条不做，一场雷雨就能换一套硬件。
  • 监控：最简单的办法是定时 curl 一次源表，搜不到自己的挂载点就发通知。掉线三天没人知道是常态。
