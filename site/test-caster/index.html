第一步：把基站的流推上来

最省事的推流方式就是用 2RTK_NTRIPserver——它就是你照基站搭建页装在盒子里那个程序。 串口、RTCM 电文、重连它都替你处理了，你只要在它的设置页里把这个测试 Caster 的地址和账号填进去。

用 2RTK_NTRIPserver 推（推荐）

浏览器打开盒子的 Web 界面 http://盒子的IP:5757，登录后进 Settings（运行设置）， 拉到 NTRIP Caster Upload 这一块，照下面填：

字段填什么
地址43.142.126.162
端口2101
挂载点你在后台自己加的名字，区分大小写
用户名 / 密码你在后台自己加的账号
上传间隔默认值就够，不用改

这一块的开关默认是关的。填完把开关打开，再拉到底点保存，服务会重启一次。 开关没开的话地址填得再对也不会推流，这一步最容易漏。

保存后回到状态页（/），10～20 秒内应该看到卫星数往上涨、RTCM 输出区开始滚报文、 Caster 那一栏的连接状态亮起来。三样齐了再往下走。

盒子还没装这个程序、或者不确定串口和波特率怎么选， 直接看 基站搭建 → 第四步：打开网页，配串口和 Caster， 那里从扫描串口到填 Caster 每一项都有截图。

用 RTKLIB 手动转发（临时验证）

手边只有电脑、想快速试一下链路通不通，用 str2str 直接串口转发：

shell · 串口推到测试 Caster
str2str -in  serial://ttyACM0:115200:1#rtcm3 \
        -out "ntrips://用户名:密码@43.142.126.162:2101/你的挂载点"

这种方式关掉终端就断了，只适合临时验证。长期跑还是用 2RTK_NTRIPserver，它有自动重连和状态页。

第二步：查源表，确认流已上线

Caster 的源表（sourcetable）就是「当前有哪些流」的清单。用浏览器打开，或者用 curl：

shell · 拉取源表并筛选自己的挂载点
# 整张源表
curl -s http://43.142.126.162:2101/

# 只看你的挂载点（把 MOUNT 换成实际名字）
curl -s http://43.142.126.162:2101/ | grep -i "STR;MOUNT"

能看到 STR;你的挂载点;… 这一行，说明 Caster 已经收到并登记了你的流。看不到的话，按这个顺序排查：

  1. 接收机推送状态是不是「已连接 / 发送中」。
  2. 挂载点名是否和你在后台添加的完全一致（大小写、有没有多余空格）。
  3. 账号密码是否被复制进了空格。
  4. 基站所在网络能不能访问外网 2101 端口（有些企业网会封非标端口）。

第三步：把流拉下来验电文

用 RTKLIB 的 str2str 把流存成文件，是最直接的验电文方式——能看清到底有没有观测数据、间隔稳不稳：

shell · 拉 60 秒存成 RTCM 文件
# 拉 60 秒，存成 rtcm3 文件
str2str -in  "ntrip://用户名:密码@43.142.126.162:2101/你的挂载点" \
        -out file://test.rtcm#rtcm3 -t 60

# 用 RTKLIB 的 rtkconv 转成 RINEX 看观测值
rtkconv -r test.rtcm

更直观的办法是用 RTKLIB 的 strsvr 图形界面：把 Input 设成 NTRIP Client， 填好参数后下面会实时显示接收的字节数、电文类型和卫星数。能看到 1005 + 各系统 MSM 在滚动，就说明数据是健康的。

连上后观察解状态：Float → Fixed 的过程通常在 5～30 秒。 如果 3 分钟还停在 Float，先确认基线和电文，再看下面这张表。

使用约定

  • 只用于功能测试：验证链路、电文、客户端配置，不做生产用途。
  • 账号和挂载点自己加：后台只增不改不删。加错了换个名字重加一个即可，不用找人处理。
  • 数据库会不定期清空：所有账号、挂载点随时可能被重置成初始状态，数据不保证保留。别把测试跑在重要作业上。
  • 服务器可能停机：这台机器由我个人出钱维持，欠费时会停。连不上就是这种情况，邮件说一声即可。
  • 不保证可用性：可能随时重启、限流或关闭，不要用在依赖连续性的作业上。
  • 不做数据留存：流转发即走，不落盘、不分析、不转售。
  • 禁止滥用：不要用它做大规模转播、压测或对外提供商业服务。
  • 坐标自负：测试数据的精度与正确性由你自己的基站决定。
