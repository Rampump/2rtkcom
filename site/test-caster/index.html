它能帮你验证什么

推流通道

接收机的 NTRIP Server 配置对不对、账号密码有没有拼错、网络能不能出公网。

电文完整性

1005、MSM 观测有没有真的在发，间隔对不对，流动站拿到后能不能固定。

拉流配置

网络质量

从你的基站到公网的上行稳定性，以及从测试点到现场的 4G 延迟与丢包。

这是测试环境，不是生产环境。不承诺可用性、不做长期数据留存、可能随时重启。 商用或长期项目请自己搭 Caster，见 NTRIP Caster 搭建。

第一步：把基站的流推上来

在接收机的「NTRIP 推流 / NTRIP Server」页面填写：

字段值
服务器 / Caster2rtk.com
端口2101
挂载点 / Mountpoint邮件里给你的名字，区分大小写
用户名 / 密码邮件里给你的账号
数据格式RTCM 3.x
自动重连打开

如果接收机没有推流功能，用树莓派或 PC 跑 RTKLIB 转发：

shell · 串口推到测试 Caster
str2str -in  serial://ttyACM0:115200:1#rtcm3 \
        -out "ntrips://用户名:密码@2rtk.com:2101/你的挂载点"

第二步：查源表，确认流已上线

Caster 的源表（sourcetable）就是「当前有哪些流」的清单。用浏览器打开，或者用 curl：

shell · 拉取源表并筛选自己的挂载点
# 整张源表
curl -s http://2rtk.com:2101/

# 只看你的挂载点（把 MOUNT 换成实际名字）
curl -s http://2rtk.com:2101/ | grep -i "STR;MOUNT"

能看到 STR;你的挂载点;… 这一行，说明 Caster 已经收到并登记了你的流。看不到的话，按这个顺序排查：

  1. 接收机推送状态是不是「已连接 / 发送中」。
  2. 挂载点名是否和邮件里完全一致（大小写、有没有多余空格）。
  3. 账号密码是否被复制进了空格。
  4. 基站所在网络能不能访问外网 2101 端口（有些企业网会封非标端口）。

第三步：把流拉下来验电文

用 RTKLIB 的 str2str 把流存成文件，是最直接的验电文方式——能看清到底有没有观测数据、间隔稳不稳：

shell · 拉 60 秒存成 RTCM 文件
# 拉 60 秒，存成 rtcm3 文件
str2str -in  "ntrip://用户名:密码@2rtk.com:2101/你的挂载点" \
        -out file://test.rtcm#rtcm3 -t 60

# 用 RTKLIB 的 rtkconv 转成 RINEX 看观测值
rtkconv -r test.rtcm

更直观的办法是用 RTKLIB 的 strsvr 图形界面：把 Input 设成 NTRIP Client， 填好参数后下面会实时显示接收的字节数、电文类型和卫星数。能看到 1005 + 各系统 MSM 在滚动，就说明数据是健康的。

第四步：流动站连上，看固定解

手簿或手机 App 里新建一个 NTRIP 配置：

字段值
Caster / Host2rtk.com
Port2101
Mountpoint你的挂载点
User / Password邮件里的账号
天线高按你的杆高如实填写

连上后观察解状态：Float → Fixed 的过程通常在 5～30 秒。 如果 3 分钟还停在 Float，先确认基线和电文，再看下面这张表。

现象基本可以确定的原因
一直 Single没连上 Caster，或挂载点/账号错
连上但零字节挂载点存在但没有源在推
一直 Float缺 1005、缺对应星座观测，或基线太远
Fixed 但坐标跳基站坐标不准 / 天线晃动 / 多路径
一分钟断一次基站侧 4G 不稳，或自动重连没开

使用约定

  • 只用于功能测试：验证链路、电文、客户端配置，不做生产用途。
  • 不保证可用性：可能随时重启、限流或关闭，不要用在依赖连续性的作业上。
  • 挂载点会回收：长期无数据的临时挂载点会被清理，需要时重新申请。
  • 不做数据留存：流转发即走，不落盘、不分析、不转售。
  • 禁止滥用：不要用它做大规模转播、压测或对外提供商业服务。
  • 坐标自负：测试数据的精度与正确性由你自己的基站决定。
